# 数据约定

主仓库定义三种数据格式，唯一定义是 `contracts/*.schema.json`（JSON Schema 2020-12）。TypeScript 类型在 `packages/course-core/src/types.ts`，由 `test/conformance.test.ts` 用同一批样例核对两边判断一致。读的一方遇到不认识的字段直接忽略；破坏性改动才升大版本。

| 格式 | 文件 | 放在哪 | 提交吗 |
|---|---|---|---|
| 跟练课程 `yangxia.course/1` | `contracts/course.schema.json` | agent 导出时放 `profiles/<代号>/课程/`；样例在 `contracts/fixtures/courses/` | 样例提交，个人课程不提交 |
| 练习记录 `yangxia.session/1` | `contracts/session.schema.json` | `profiles/<代号>/打卡/` | 不提交 |
| 个人档案 `yangxia.profile/1` | `contracts/profile.schema.json` | `profiles/<代号>/档案.json` | 不提交 |

模板发布物 `yangxia.manifest/1` 由模板仓库定义（模板 `docs/架构说明.md` 第十节）。主仓库在 `contracts/templates.json` 里写明只认这个格式号。

## 一、跟练课程

一天的训练，**按成品原样导出**，不是重新编。

- `age`：年龄段代码（a13、a18、a40、a65），和成品一致。6–12 岁版写明"不用组数、不用次数"，全家餐饮没有训练，都不导出。
- `source`：出自哪份成品、第几周、哪天。
- `blocks`：`sets` 是做完一个动作的所有组再换下一个；`circuit` 是几个动作轮流做 `rounds` 轮，每个动作每轮 1 组，轮间休息 `restBetweenRounds`。
- 每个动作：
  - `exercise` 是模板动作索引的 ID，`name` 用索引里的短名。
  - `mode` 是 reps 或 timed，`perSide` 表示左右各做一遍；这两项都要和动作索引一致。
  - `reps` 或 `duration`，以及 `rest`（这个动作每组后休息几秒）。
- `tempo`（按次计数的动作才有）：单位是**秒**，以 0.5 秒为单位。
  - `start` 表示一次动作从发力（up）还是下放（down）开始。深蹲、俯卧撑先下放；划船、臀桥、弯举先发力。
  - `up` 发力，`top` 顶点停，`down` 下放，`bottom` 底部停。
  - BPM 只管背景鼓点，不影响动作时长。
- `quote`：**成品原文**，1–4 段。组数、次数、秒数、休息都要能在这里找到出处。每段只摘本周那一句。
- **区间取较轻松的一端**：次数、组数、时长取下限，休息取上限。以后加量由周复盘按成品的升级规则决定。
- `presentation.sequencer`：编排器怎么播（音色、领呼、鼓点、画面），别的项目可以忽略。默认值见 `packages/course-core/src/settings.ts`。

## 二、课程检查

```bash
npm run course -- check <课程.json> --profile <档案.json>
```

有错误时退出码为 1。逐项核对：

1. 格式和数值范围。超出范围直接报错，**不悄悄改值**。
2. 动作在动作索引里，而且用在这份成品；计次 / 计时、是否每侧和索引一致。
3. 每段 `quote` 逐字出现在成品里（加粗记号和多余空格不算）。
4. 不能用别的周的原文：
   - 原文里写了"第 N 周"的，要包含本周。
   - 原文落在"一列一周"的表格里的，只能取本周那一列；本周格子写"同第 N 周"的，也可以取第 N 周那一列。
5. 组数（"N 组"）、次数（"N 次""× N"）、时长（"N 秒"）在原文里有出处，区间按上面的规则取。
   - 休息只看原文里"休息"或"歇"之后的秒数，以及健身房训练表的"90″"写法。
   - 休息 0 秒要有"不休息"之类的原文。
   - 轮数（"N 轮"）和轮间休息同样要有出处。
6. 节奏秒数出现在这个动作在这份成品里的呼吸节奏原文中（"约 2 秒""2–3 秒""半秒"都认）。
7. 时间轴生成的字幕、画面文字没有这个年龄段的红线词；这里**不用白名单**，所以 65 岁以上连"不憋气"都不能出现。语音只用内置词表里的说法。
8. 带 `--profile` 时：
   - 安全筛查有"是"而医生没同意，或者 65 岁以上医生没同意，直接拒绝。
   - 没做筛查的档案也拒绝。

**查不出来的**（agent 仍要自己守规矩）：

- 原文是从成品里摘的，但是不是**这一天**的动作，检查只核对成品和周次，不核对训练日。
- 一段原文同时写了几周时，只能给警告，核对不出数字属于哪一周。所以每段只摘本周那一句。
- 热身、拉伸、有氧（单车、跑步机）不在动作索引里，不导出成课程。
- 左右**交替**做的动作（死虫式、平板肩点）：`perSide` 表示"左边做完再做右边"，表达不了交替，按交替报数会报错次数，所以暂不导出。以后要支持，需要在课程格式里加一个"交替"标记。

样例：`contracts/fixtures/courses/ok-*.json` 覆盖 8 份训练成品，`bad-*.json` 是格式不合格的样例。离线测试用的成品原文片段和 manifest 片段由下面的命令生成，模板更新后要重新生成：

```bash
node packages/course-core/test/make-fixtures.ts
```

## 三、个人档案

- `code`：代号，也是 `profiles/` 下的目录名，**不用真名**。
- `stage` / `age` / `venue` / `product`：按模板 manifest 的 `intake` 问卷选出来的。
- `wake` / `bedtime`：上床时间 = 起床时间 − 目标睡眠 − 入睡缓冲 20 分钟。
- `screening.answers`：逐项"是 / 否"，**不记病名和用药**。
- `screening.doctorCleared`：使用者说医生已经同意开始。65 岁以上必须为 true；其余年龄段有任何一项"是"时必须为 true。agent 只能照使用者说的记，不能替使用者判断。
- 样例：`contracts/fixtures/profiles/ok-a18-home.json`。

## 四、练习记录

编排器练完导出，周复盘读它：

- 练的是哪个课程、开始和结束时间。
- 每个动作计划几组、完成几组、有没有跳过。
- 主观感受：轻松、正好、吃力。
- `symptoms`：疼痛、头晕、胸痛胸闷。任何一项为 true，下周不加量，按成品"疼了怎么办"处理，必要时建议就医。
