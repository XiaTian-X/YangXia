# 数据约定

主仓库定义四种数据格式，唯一定义是 `contracts/*.schema.json`（JSON Schema 2020-12）。TypeScript 类型在 `packages/course-core/src/types.ts`，由 `test/conformance.test.ts` 用同一批样例核对两边判断一致。读的一方遇到不认识的字段直接忽略；破坏性改动才升大版本。

| 格式 | 文件 | 放在哪 | 提交吗 |
|---|---|---|---|
| 跟练课程 `yangxia.course/1` | `contracts/course.schema.json` | agent 导出时放 `profiles/<代号>/课程/`；样例在 `contracts/fixtures/courses/` | 样例提交，个人课程不提交 |
| 练习记录 `yangxia.session/1` | `contracts/session.schema.json` | `profiles/<代号>/打卡/` | 不提交 |
| 个人档案 `yangxia.profile/1` | `contracts/profile.schema.json` | `profiles/<代号>/档案.json` | 不提交 |
| 复盘数据 `yangxia.review/1` | `contracts/review.schema.json` | `profiles/<代号>/复盘/<开始日期>-第N周.json` | 不提交 |

模板发布物由模板仓库定义：`yangxia.manifest/1`（模板 `docs/架构说明.md` 第十节）、训练单 `yangxia.plans/1` 和规则参数 `yangxia.rules/1`（模板 `docs/训练单格式.md`，在 `dist/data/`），可选的跟练动图 `yangxia.motions/1`（模板 `docs/架构说明.md`，`dist/data/motions.json`，编排器打包时嵌入，没有也能用）。主仓库在 `contracts/templates.json` 里写明只认这些格式号；模板没有训练单时，导出和进度核对提示先更新模板。

## 一、跟练课程

一天的训练，**由 `course export` 从训练单导出**，不是重新编：

```bash
npm run course -- export profiles/<代号> <第几周> <哪天> [--out <文件>] [--pick 组=动作]
```

agent 只选哪一天；组数、休息来自训练单，次数、难度级、重量来自档案的个人进度，节奏来自呼吸节奏原文、难度级和"下放放慢"规则，条件变体按档案的 `conditions`（没记的按模板规则层"没确认时"的保守版本），"按器材选一个"按档案的 `choices`，轮换按周次或这一段练过几次（`--pick` 可以指定，写进 `source.picks`）。照成品做的项（交替动作、等长对抗、有氧、原文有歧义的减量日……）、本周不做、有时间可以加、时间不够先砍，命令会列出来，agent 照原文转告。导出后自动跑一遍课程检查，0 错误才写文件（默认 `课程/第N段-第N周-X日.json`）。

- `age`：年龄段代码（a13、a18、a40、a65），和成品一致。6–12 岁版写明"不用组数、不用次数"，全家餐饮没有训练，都不导出。
- `source`：出自哪份成品、第几周、哪天；导出的课程还有 `plan`（`yangxia.plans/1`）、`segment`（第几段）、`type`（标准 / 减量）、`phase`（起始 / 稳定；稳定期的 `week` 是 1–12，导出的是这一轮对应那一周的处方；稳定期不能回头导出"一轮里的周次"比现在大的周——上一轮第 3、4 周比这一轮第 1 周重）、`picks`（轮换组选了哪个）。
- `blocks`：`sets` 是做完一个动作的所有组再换下一个；`circuit` 是几个动作轮流做 `rounds` 轮，每个动作每轮 1 组，轮间休息 `restBetweenRounds`。
- 每个动作：
  - `exercise` 是模板动作索引的 ID，`name` 用索引里的短名。
  - `mode` 是 reps 或 timed，`perSide` 表示左右各做一遍；这两项都要和动作索引一致。
  - `reps` 或 `duration`，以及 `rest`（这个动作每组后休息几秒）。
- `tempo`（按次计数的动作才有）：单位是**秒**，以 0.5 秒为单位。
  - `start` 表示一次动作从发力（up）还是下放（down）开始。深蹲、俯卧撑先下放；划船、臀桥、弯举先发力。
  - `up` 发力，`top` 顶点停，`down` 下放，`bottom` 底部停。
  - BPM 只管背景鼓点，不影响动作时长。
- `quote`：**成品原文**，1–4 段。组数、次数、秒数、休息都要能在这里找到出处。每段只摘本周那一句。
- `figure`（可选）：动作示意动图的片段号（模板 `dist/data/motions.json` 的键）。`course export` 写，这一级有合适的动图才有；手写课程不写，写了课程检查报错。
- **区间取较轻松的一端**：次数、组数、时长取下限，休息取上限。以后加量由周复盘按成品的升级规则决定。
- `presentation.sequencer`：编排器怎么播（音色、领呼、鼓点、画面，`motionFigure` 是显示动作示意，默认开），别的项目可以忽略。默认值见 `packages/course-core/src/settings.ts`。

v4 阶段 2 起，`source.half: true` 是半量课（中断、生病回来的第一次，`course export --half`）：每个动作组数、循环轮数减半向上取整（设计值 `HALF`），次数、秒数、休息不变；课程检查按半量核对；照样算训练次数，但不当加量依据。

## 二、课程检查

```bash
npm run course -- check <课程.json> --profile <档案.json>
```

有错误时退出码为 1。不带档案要显式写 `--no-profile`（只用于样例和开发，结果不能据此把课程交给使用者）。

**从训练单导出的课程**（`source.plan`）：用同一份档案重新导出一遍，逐项比对动作和顺序、组数或轮数、次数或秒数、休息、节奏、是不是每侧；档案进度变了、段变了，旧课程要重新导出。训练单和成品正文的一致由模板仓库保证（表格独立推一遍比对、原句逐字核对、漏转核对）。**起点课程**（标准段、条件取正文那一边、每个动作起始级、次数取下限）再跑一遍下面的原文核对作第二层，它报的问题记成警告（原文核对有认不出的写法，见本节末尾"原文核对的已知限制"）；带进度、带条件变体、减量段的课程不跑原文核对。

`course check --profile <档案目录>/档案.json`（只认档案目录里的 `档案.json`）和 `course export` 还会先核对整个档案目录的周复盘和个人进度（第三之二节），有错误就不放行、不导出。第二层原文核对里"出处原文在成品里找不到"是错误（训练单给的出处必须逐字在成品里）。课程的名称也逐项比对（难度级只靠名称区分，比如"徒手深蹲·抱装书的背包"）。

**手写的课程**（没有 `source.plan`）：带档案检查、模板有训练单时直接报错（原文核对管不了条件、进度和训练日）；不带档案的（样例、开发用）照旧逐项做原文核对，并提醒改用 `course export`。原文核对：

1. 格式和数值范围。超出范围直接报错，**不悄悄改值**。
2. 动作在动作索引里，而且用在这份成品；计次 / 计时、是否每侧和索引一致。
3. 每段 `quote` 逐字出现在成品里（加粗记号和多余空格不算）。
4. 不能用别的周的原文：
   - 原文里写了"第 N 周"的，要包含本周。
   - 原文落在"一列一周"的表格里的，只能取本周那一列；本周格子写"同第 N 周"的，也可以取第 N 周那一列。
5. 组数（"N 组"）、次数（"N 次""× N"）、时长（"N 秒"）在原文里有出处，区间按上面的规则取。数字还要**出自对的原文**，不能借别的周、别的动作的：
   - **组数、轮数**只认本周的原文：写着本周的（"第 1 周（2 组，边学边练）""第 1–2 周做 3 轮"），或"一列一周"表格里本周那一列。动作库里"3 组 × 15–20 次"是目标处方，不能当第 1 周的组数。
   - **次数、时长**只认这个动作自己的原文（动作索引摘到的它在本成品的处方、标题，或者写着它名字的那一句），或者本周的原文。
   - 原文所在的那一行说的是别的动作（写着别的动作名、没写这个动作），不算这个动作的出处。表格行只看行首那一格和摘到的那几格。
   - 同时写了别的周的句子不算本周的出处；行首写着本周的表格行（"| 第 4 周 | 3 组 | …把第 3 周做扎实"）算本周。
   - "一列一周"的表格：别的周的格子和本周格子内容一样不算借；本周那一格写着"不做"的，直接拒绝；"同第 N 周"按第 N 周那一列算。
   - 休息只看原文里"休息"或"歇"之后的秒数，以及健身房训练表的"90″"写法。
   - 休息 0 秒要有"不休息"之类的原文。
   - 轮间休息同样要有出处。
6. 节奏秒数出现在这个动作在这份成品里的呼吸节奏原文中（"约 2 秒""2–3 秒""半秒"都认）。有条件的写法只在条件成立时算：
   - 写明周次的（"第 3 周起放慢到 3 秒"）只在那几周算；
   - 写明"那一级"的（"下放 3 秒那一级"）是难度阶梯，不按周给，本周的原文写了（如第 3 周那一行"下放放慢到 3 秒"）才算；本周原文里说下放的秒数只给下放用，说停的只给顶点、底部停用。
7. 成品写明"第 N 周开始做"（如 65 岁以上的脚跟脚尖走）、"下一轮才用"（如保加利亚分腿蹲）的动作，不能提前导出：动作索引的 `used_in[].from_week`、`from_round` 由模板构建时从标题摘出；轮次取档案现在是第几段。
8. 时间轴生成的字幕、画面文字没有这个年龄段的红线词；这里**不用白名单**，所以 65 岁以上连"不憋气"都不能出现。语音只用内置词表里的说法。
9. 带 `--profile` 时：
   - 课程要出自档案选的成品；课程周次不能超过档案 `segments` 最后一项的周次（下一周要等周复盘放行）。
   - 档案本身要合格（第三节），而且和模板对得上（见"和模板核对"），筛查少答、改字都拒绝。
   - 安全筛查有"是"而医生没同意，或者 65 岁以上医生没同意，直接拒绝。
   - 没做筛查的档案也拒绝。

**查不出来的**（agent 仍要自己守规矩）：

- 原文是从成品里摘的，但是不是**这一天**的动作，检查只核对成品和周次，不核对训练日。
- 一段原文同时写了几周时，只能给警告，核对不出数字属于哪一周。所以每段只摘本周那一句。
- 热身、拉伸、有氧（单车、跑步机）不在动作索引里，不导出成课程。
- 左右**交替**做的动作（死虫式、平板肩点）：`perSide` 表示"左边做完再做右边"，表达不了交替，按交替报数会报错次数，所以暂不导出。以后要支持，需要在课程格式里加一个"交替"标记。

**原文核对的已知限制**（起点课程上它只给警告，以训练单核对为准）：

- "4 组（第 1 周 3 组）"、墙面天使"2 组 × 10 次"这类动作标题自己写的组数，没写本周，原文核对认不出是第 2 周起的组数；
- D 日循环那句"第 1–2 周做 3 轮，第 3–4 周做 2 轮"同时写了两种周次，只能给"同时写了几周"的警告；
- 原文所在那一行提到了别的动作（如面拉"做法"里提到别的器械、循环里"握力累了就换成超人式"、13–17 岁递进表那一格提到"跳跃组"），原文核对就不把它当这个动作的出处。
2026-11-08 的全量核对：8 份成品标准段每周每天的起点课程（112 份）训练单核对 0 错误，原文核对的警告都属于上面这几类。

样例：`contracts/fixtures/courses/ok-*.json` 覆盖 8 份训练成品，`bad-*.json` 是格式不合格的样例。离线测试用的成品原文片段、manifest 片段、训练单和规则参数（`contracts/fixtures/data/`，6 份成品的节选）由下面的命令生成，模板更新后要重新生成：

```bash
node packages/course-core/test/make-fixtures.ts
```

## 三、个人档案

- `code`：代号，也是 `profiles/` 下的目录名，**不用真名**。
- `stage` / `age` / `venue` / `product`：按模板 manifest 的 `intake` 问卷选出来的。`product` 等于 `segments` 最后一项的成品。
- `wake` / `bedtime`：上床时间 = 起床时间 − 目标睡眠 − 入睡缓冲 20 分钟。
- `birth`：成年人的出生年月 `YYYY-MM`（**只记到月**，必填；不在校的 13–17 岁也记）。年龄按出生月份的 1 日算，满 40 岁、满 65 岁换版靠它推算（设计值 `AGE_BY_MONTH`）。
- `school`：在校未成年人的学段 `{ stage: 小学 / 初中 / 高中, entry: 入学年份, system: "63" / "54" }`（学制默认六三制），必填。按 9 月 1 日升学推算（`SCHOOL_SEP1`）；高中毕业而且满 18 岁才换成人版（`GRAD_18`），这时补记 `birth`。
- `screening.answers`：逐项"是 / 否"，**不记诊断细节和用药**。
- `screening.date`：做筛查的日期（必填）。超过 365 天要做触发评估、重做筛查（`SCREEN_YEAR`；65 岁以上另外按官方每年做一次跌倒风险评估）。
- `screening.doctorDate`：医生同意的日期（`doctorCleared` 为 true 时必填）。**有效的医生同意**要不早于最近一件要医生同意的事：筛查日期（有"是"或 65 岁以上）、65 岁以上摔倒的那一周、40–64 岁开工前提没过的那次评估——重做筛查、摔倒以后都要重新确认。
- `body`：18–64 岁记不记体重、腰围：`记` / `不记` / `停记`（默认不记；出现节食、焦虑改"停记"，同时写 `bodyStopDate` 停记那天——以前评估里记的保留，之后的新记录不能再有身体数据）。6–17 岁、65 岁以上不能写"记"。
- `bodyLog`（v4 阶段 4）：每次改"记 / 不记 / 停记"的日期 `[{ date, body }]`，按日期从早到晚；写了的，最后一项要等于 `body`，最后一次停记要等于 `bodyStopDate`。没写的由 `body`、`bodyStopDate` 推（停记那天以前按记）——**建档以后改过记不记的、选过减脂增肌的一定要写**（停记以后改回记、记过以后改成不记，没写都报错；第一次改时先补一项建档那天的状态）。评估里的身体数据、复盘里的体重都按**记录那天**的状态判断。身高只记一次（入门；建档时没记、改成记以后的第一份评估），BMI 一律用最早那份身高；"中断"触发评估只有真的断过 28 天以上才能记一次身体数据。
- `cardioClear`（v4 阶段 4）：减脂加有氧的医生同意 `[{ date }]`（续了就加一项，每一周用当时有效的那一次）——有高血压（或没确认）、筛查有"是"的人要有，日期不早于最近一次重做筛查和最近一件要医生同意的事、365 天以内；没有的，减脂的有氧照保持的量，**没有有效同意的周不算进升档**，同意以后从第一档开始。
- `addClear`（v4 阶段 6b）：65 岁以上稳定期加项的医生同意 `[{ date, items }]`——医生说可以照这份计划一轮加一项的那天、同意的那几项（加项 ID：`sit12` 坐站起每组加到 12 次、`sit3sets` 坐站起加第 3 组、`stance30` 前后脚站到 30 秒、`step` 上下台阶，模板 `稳定期.md` 的"加项"表），按日期从早到晚，365 天有效。加新的一项用严格算法（重做筛查、摔倒、生病住院、看完医生回来这些事一出旧的就不算）；已经加上的项用"看了医生才算"的算法去留（失效的那一周起去掉）。
- `addOnLog`（v4 阶段 6b）：65 岁以上稳定期哪天加了 / 减了哪一项 `[{ date, item, action: 加 / 减, why }]`。加：只在一轮的第 1 周、上一轮 ≥ 10 练（每周最多算 3 次）、上一轮没有摔倒差点摔倒头晕和疼痛、有效的 `addClear` 里有这一项、一轮最多一项、坐站起两种只能选一种、`step` 要条件"家里没有别人"记了"否"、上一个周期末"第一轮不升级"的第 1 轮不加；减：随时可以。回起始期、看完医生回来、同意失效时清零或去掉由命令算，不用写。导出时按有效的加项改坐站起的次数上限（12）或组数（3）（训练单不动）；`sit12` 去掉以后导出按 10 截，个人进度里留着的次数不算错。
- `weightClear`（v4 阶段 5）：肥胖（BMI 28.0–32.4）选减脂的医生同意 `[{ date }]`——医生说可以按这份计划减重（每天少吃约 300 kcal、有氧逐步加到每周 250 分钟）的那天，写法、有效期和 `cardioClear` 一样，有效时同时算作有氧加量的同意；每一周开始时最近一次称的 BMI（评估里量的、减脂复盘里称的）在 28 以上的减脂周都要有有效的同意：过期了，或者重做筛查、有了新的要问医生的事以后**看了医生没续**，看医生以后开始的那一周起退回保持；还没看医生的那几天导不出课程，旧的同意照算，看医生时续上的不算失效（看医生的日子按 `screening.doctorDate` 和"看完医生回来"触发评估的 `doctorDate`）。开周期时超重、周期里称到 28 以上又没有同意的，下一周起退回保持。**有氧台阶另算**（`weightClear`、`cardioClear` 都一样，照成品《目标》一节）：事情一出（重做筛查、生病住院、摔倒……）旧的同意就不算，到看医生续上为止这几周有氧照保持的量、不算进升档，续上以后从 100 分钟那一档重新开始。BMI 32.5 以上不在这份计划里减重，只保持。
- `dietByPro`（v4 阶段 5）：医生或营养师给了自己的减重方案 `[{ date, pro }]`——给了方案（`pro: true`）、不再照它（`pro: false`）的那天，按日期从早到晚，每次变了加一项。周期开始时是 true 的，目标只选保持；周期中途记的，记以后开始的周起退回保持（那一周已经开始了，吃当天起照他们的）——和停记、改不记"改动那一周起"不一样：停记是出了节食、焦虑，那一周就不再称、不再按减脂，计划单当场重做；有了专业方案只是吃换成照他们的，那一周的有氧、称重照常，不用重做计划单；计划单按那一周开始时的写"吃照医生、营养师给你的方案"。
- 条件 `重度肥胖`（v4 阶段 5，推出来的）：那一天还是"记"、量过体重的（评估里量的、减脂复盘里称的），按最近一次的 BMI ≥ 37.5 算，不管隔了多久；没量过的、改成不记或停记的看档案 `conditions.重度肥胖`（报身高体重当场算，只记是 / 否；满一年重做筛查、"BMI ≥ 28"还是"是"的时候重问）；也没有的看筛查"BMI ≥ 28"那一项。计划单、导出都按那一周开始那天推。是的、有氧没问过医生的，徒手、居家版每一轮第 3–4 周的间歇写稳态；健身房版不受影响。
- 官方食养指南（v4 阶段 5b、6c）：成人、65 岁以上成品末尾有《附：官方食养指南》；6–12 岁家长版列儿童青少年两份（给家长看），全家餐饮列全 11 份、分两组（给家长看孩子的 2 份、给家里成年人和老人的 9 份，成人肥胖那一份只给 18–64 岁）；13–17 岁版不列（孩子本人读）（模板 `content/params/食养指南.md`，只放名称、文号、通知页和"本指南主要面向……"原话）。计划单只指路、不改饮食：筛查第 3 项"是"的写"吃照医生的意见 + 附录"；条件高血压、骨质疏松记了"是"的写"官方有《……食养指南》，这份计划的饮食照常"；没确认的不写。
- 附册（manifest `phase: "附册"`、场地 `book`，如《18-39岁-超重与肥胖（附册）》）不能选成档案的 `product`、`segments[].product`；BMI 24 以上（或没记体重、筛查"BMI ≥ 28"是）的人，计划单写一句指向同一年龄段的附册。
- `segments[].goal`（v4 阶段 4）：这一周的目标 `保持`（默认，不写）/ `减脂` / `增肌`，只给 18–64 岁稳定期；一段（周期）里只能从减脂、增肌退回保持，退了不能改回去、不能换成另一个。见下面《稳定期的目标》。
- `habitBase`：65 岁以上建档时定的散步时长 `{ "散步": 分钟 }`（65 岁以上必填），"散步减 5 分钟"按它算。
- 日期照实写：`screening.date`、`doctorDate` 和评估里的日期都不能晚于今天。档案记了医生同意、但日期早于最近一件要医生同意的事（重做了筛查、摔倒、生病住院……），是**错误**（要重新问医生）；还没同意的，档案检查给警告，导出、带档案的课程检查都拦下。档案的 `doctorDate` 要不早于最近一份"看完医生回来"触发评估里的医生同意。
- `screening.doctorCleared`：使用者说医生已经同意开始。65 岁以上必须为 true；其余年龄段有任何一项"是"时必须为 true。agent 只能照使用者说的记，不能替使用者判断。
- `segments`：每一周一项 `{ n, phase, type, week, start, product }`：第几段（起始期 4 周一段，稳定期 12 周一段）、阶段（`起始` / `稳定`，不写按起始）、段型（标准 / 减量；稳定期只有标准）、这一段的第几周（起始期 1–4，稳定期 1–12）、从哪天开始、用哪份成品。建档写第一项（第 1 段第 1 周、从 `startDate` 开始）；周复盘每次追加一项：按成品规则放行就加 1 周，没达标或有不适就不变；第 4 周复盘后按成品"下一轮的方向"新开一段（`n` 加 1、从第 1 周起，段型照选的那一条）；换成品（跨年龄段、换场地）也新开一段。每一项至少 7 天，开始日期最晚是明天；同一段里成品和段型不变、每次最多推进一周、不往回走。旧的 `week`、`round`、`weeks` 不再用。v4 阶段 2 起，段的第一项可以带：
  - `habitTargets`：上一段段末结论给的习惯目标 `{ 打卡项: { days } / { minutes } / { line } }`（13–17 岁降到每周 4 天、65 岁以上散步减 5 分钟、6–12 岁成功线降到 16 天），只能照段末评估重算的结果写；
  - `restart`：同一成品在一段中途从第 1 周重来（65 岁以上生病住院回来、6–12 岁生病超过 7 天），写依据的触发评估 `评估/<日期>-触发.json`（要是被中断那一段里、新一段开始之前的；生病住院的要有 `eventDate` 和之后的医生同意）。重来那一段的段型、习惯目标照被中断的那一段；上一段已经练完第 4 周的，照样要段末评估、照段末结论开。
  - 这两项只写在一段的第一项。
  - **稳定期的段**（v4 阶段 3）：`phase: "稳定"`，`product` 写稳定期成品（和同一年龄段、场地的起始期成品是一个**家族**，代码相同，如 `a18·bw`；家族内换成品进度接着用、不重新建档，也不用"换场地"评估）。一段 12 周 = 3 轮，每一轮照起始期标准段第 1–4 周的训练单；**一段只在第 12 周结束**（做周期末评估，第六节）。`phase` 要和成品的类型一致、同一段里不变。
  - 进稳定期只有两条路：同一家族的起始期练完一段、段末结论到了进阶线（模板 `稳定期.md` 的"进稳定期的结论"，而且是"往上"那一条）而且没被不适降级；或者有基础的人建档时直接进入（第一段就是稳定期：入门评估 `base` 和俯卧撑测试达线、`focus` 含"训练"，只限"直接进入：是"的成品——成人徒手、居家）。换场地、换成品不能直接进稳定期。模板登记了"进稳定期要习惯达标"的（13–17 岁，v4 阶段 6a），段末重算出的下一段习惯目标还要是空的（`STABLE_ENTRY_HABITS`：降过的都已改回）。
  - 换到别的家族的成品（如小学升初中），上一段的习惯目标**不带过去**，新一段不写 `habitTargets`；6–12 岁那几段不算进中断，从换到新成品那一段开始那天起算（`CROSS_FAMILY_RESET`）。
  - 稳定期一个周期没练完就回起始期，要有触发评估（中断、`doctorRestart`、"回起始期"），回同一家族起始期的标准段；满 40 岁在轮的边界（第 4、8、12 周之后）换到 40–64 岁的起始期，从满 40 岁那个月起先做跨段的触发评估、补上体检和血压，否则不出课程；断了超过 56 天（`GAP_RESTART`）要回起始期。
- `focus`：有基础的 18–64 岁想先从哪方面入手 `{ areas: [作息 / 饮食 / 训练] }`（可多选）；直接进稳定期的人要含"训练"。减脂、增肌的目的后面的阶段才有，现在不记。
  - 下一段的段型（细化方案第十三节，用户已定）：照段末结论；这一段有过不适，往上的结论降级——标准段降为"原样"，减量段再来一段减量段（"回标准段"也算往上）；65 岁以上"先看医生"、医生同意以后，跳过那一条照后面几条走，往上的同样降级（≥ 10 练只给"原样"）；换场地、换成品继承段型（减量段换场地还是减量段），习惯目标只留新成品也有的打卡项。
- `conditions`：训练单用到的几项条件（高血压、有氧问过医生、骨质疏松、家里没有别人、没地方跳、家长在旁边），每项只记 true / false，建档时如实告诉使用者；没记的按模板规则层"没确认时"导出保守版本。
- `choices`：能用的器材对应的选项，按优先顺序，写训练单里的原样：动作 ID（如 `"door-row"`），或带括号的占位（如居家版的 `"（门框划船）"`，导出时列在"照成品做"）；训练单"按器材选一个"时取第一个这一行有的。
- `progress`：个人进度 `{ 动作或阶梯 ID: { level, reps, weight } }`：难度级、每组次数、健身房重量（**按公斤记**，器械按配重片换算成公斤；不记"第几片"，否则"每档最多 25%"没法算）。没写的按训练单的起始级、区间下限。
- `progressLog`：进度每一次改动 `{ date, move, field, to, rule, evidence }`。`rule` 是 建档 / 找级 / 退回 / 减量 / 升级 / 加次数 / 加一档 / 调重量 / 加重 / 重来，`evidence` 写依据的练习记录（`打卡/…`）或复盘数据（`复盘/….json`）。只能经它改 `progress`：
  - 建档：这份成品开始那天记起始难度级和次数（次数取区间下限，难度级要是第 1 周能用的级）；健身房的起始重量在开始那一周里第一次练的时候记。换成品那天在新成品里重新建档（各成品的级号意思不同，不重新建档会报错）。
  - 找级（找级周，成人居家徒手、13–17 岁第 1–2 周）：一次上下一级。依据是找级周里、这条改动之前、这个动作上一次改动之后的练习记录，这个动作练过、不是手改过的课程，感受是"做到上限还很轻松"（升）或"做不到下限或后面几下变形"（降）。一份记录只能给一个动作用一次。
  - 退回：降回上一级，依据是这一天之前的练习记录里这个动作标了"当场退回"。减量（降级、减次数、减重量）随时可以。
  - 升级（升级周：18–39 岁和 13–17 岁每一轮第 4 周——稳定期就是第 4、8、12 周）：成品的"达标"——依据是**紧挨着的上一周**的复盘数据，里面这个动作每组都做到区间上限、最后一组还有余力；升级后次数回到区间下限。
  - 升级（40–64 岁，设计值 `A40_UPGRADE_WINDOW`，窗口取模板 `进度.md` 的"下一轮升级窗口"）：第 1 轮不升；第 2 轮起每一轮**第 1–2 周**可以升（起始期、稳定期同一个口径），第 3–4 周级别不动；**每周最多升一个动作**（"一次只升一样"），**同一个动作一轮只升一级**（上一轮是在原来那一级达标的）；依据是**上一轮第 3 或第 4 周**的复盘数据（3 组的周；本轮第 1 周只有 2 组，不当依据），每份复盘每个动作只用一次。
  - "第几轮" = 同一年龄段里练完的 4 周轮数 + 1：起始期练到第 4 周的一段算一轮（练 1 周就换成品不算），稳定期每满 4 周算一轮（被提前截断的只算练满的）。直接进稳定期的人从第 1 轮起；从起始期升上来的人，稳定期第 1–4 周至少是第 2 轮。
  - 加次数：每次加 1–2 次，不超过区间上限；依据是紧挨着的上一周的复盘数据，这个动作每组都做满当前次数（`allDone`）、最后一组还剩 4 次以上余力（设计值 `PROGRESS_REPS_SPARE`，比目标"留 2–3 次"还轻松）；65 岁以上还要连着两次训练都轻松（`easyTwice`）。次数由周表定的动作（健身房主项、循环）不记次数。
  - 调重量（健身房第 2 周）：依据是这一周、这条改动之前的练习记录里"还能做几下"6 下以上；加重（健身房第 3 周）；第 4 周不加重。加一档最多加原重量的 25%（设计值 `GYM_STEP_MAX`）。
  - **稳定期的找级只给**（设计值 `STABLE_FIND`）：直接进稳定期的人的第 1 轮第 1–2 周；**真的**断了 28 天以上（那份"中断"触发评估之前最后一次训练到它超过"长时间中断天数"）、做过触发评估回来的头 14 天（不论周次），依据要是做完触发评估以后练的那一次。其他人在稳定期只能往下调（减量、退回）；没有对应中断的"中断"评估只给提醒、不能拿来找级；家族外换成品的人走新成品的起始期，照起始期找级。
  - **健身房稳定期双进阶**（设计值 `GYM_DOUBLE_RULES`；健身房稳定期的训练单由起始期第 4 周派生到第 1–12 周，周表定次数的主项次数 10–12 走个人进度、训练单那一行标 `double`，设计值 `GYM_STABLE_PLAN`；**只有标了 `double` 的行走双进阶**，提踵、平板支撑、死虫式、面拉、农夫行走照原文"照旧按动作库"，不加次数、不加一档。起始期没记起始重量的，稳定期第 1 周可以补记"建档"）：加次数——依据是**最近一次**练这个动作的练习记录（这个动作上一次改动之后练的、它之后没有再练过这个动作、不是手改的课程、不是半量课；余力门槛取模板 `进度.md` 的"双进阶加次数余力""双进阶加一档余力"），每组都做完、"还能做几下"≥ 3 → 下一次 +1，不超过区间上限（12）；加一档——次数已经是 12、每组都做完、"还能做几下"≥ 2、没有当场退回 → 重量加一档（≤ 25%），次数回到 10。这两条不受"每周最多一次"限制，由"每份记录每个动作只用一次、要晚于上一次改动"管；稳定期不用调重量、加重。
  - **稳定期的不适按轮算**（`STABLE_SYMPTOM`）：一轮（4 周）里出现过疼痛、头晕、胸闷，这一轮后面不往上加；下一轮要先有一周没有不适的复盘才放开。上一个周期末结论是"习惯没达标"的，这个周期头 4 周不升级（健身房：不加次数、不加一档）。
  - 往上调的（找级升、升级、加次数、加一档、调重量、加重）：这一段里出现过疼痛、头晕、胸闷（练习记录或复盘数据），或者上一周有，就不行；同一个动作同一天只往上改一样；升级、加次数、调重量、加重每个动作每周最多一次；依据那一周的复盘有不适也不行。
  - 重来（65 岁以上生病、住院回来，`A65_RESTART`）：只在写了 `restart` 的那一段开始那天，依据就是那份触发评估，改回训练单的起始级、区间下限（只能往下）。
  - 半量课（`source.half`）的练习记录不当找级、调重量的依据；复盘数据写了 `half: true` 的那一周不当升级、加次数的依据。
  - 上一段有过疼痛、头晕、胸闷：这一段要先有一周没有不适的复盘，才能按"下一轮升级"往上升（`SYMPTOM_CARRY`）。
  - 第 2 轮起，难度级按阶梯表"成品 + 以后"放开（成品："下一轮第 1 周直接用记录表里最后定下的难度级"），但条件变体写的级上限一直生效；建档只能用第 1 轮这一周起步能用的级，放开的级要一级一级升上去。
  - `npm run profile -- check` 重放 `progressLog`，逐条按这些规则核对，结果要等于 `progress`。
- `household`：排菜单时记，一起吃饭的家庭成员（含自己）的年龄段，如 `["a40", "a13"]`。只记年龄段，不记名字。

- `product` 是模板里的成品，年龄段一致；写了 `venue` 的，和成品场地一致。全家餐饮模板不是个人计划，不能当 `product`。

- 属于问卷"不覆盖的人群"的筛查项（孕期、产后 6 个月内）答了"是"：不出计划，医生同意也一样。
- 写了 `wake` 和 `bedtime` 的，`bedtime` 等于公式算出来的时间。

`npm run profile -- check profiles/<代号>` 检查整个目录：

- 档案（含和模板核对）、课程、练习记录、复盘数据、复盘和菜单的红线；
- 课程：这一段这一周导出的逐项核对；档案进度在导出之后改过、而它对得上改动之前那天的进度的，只提醒"要练就重新导出"——但那之后进度往下调过、或者有过不适的，报错（旧课程比现在重）；以前几周、几段导出的只核对格式并提醒；`历史/` 下的只核对格式；
- 菜单按全家餐饮、档案主人和 `household` 里每个年龄段的红线查；有菜单却没记 `household` 报错；
- **周次推进**（按 `segments` 的日期）：除了正在进行的最后一周，每一周都要有复盘（`.md` 和 `.json`）；复盘数据的训练次数不能少于这一周的练习记录数，练习记录里有不适、复盘不能写没有；某一周有疼痛、头晕、胸闷，同一段的下一周不能往上走（挪进 `历史/` 的记录，日期落在这些周里的照样算）；
- **个人进度**：重放 `progressLog`，逐条按规则核对（第三节），结果要等于 `progress`；`conditions` 的条件名要是模板规则层有的；
- `历史/` 下只放以前几段的文件：`历史/第N段/…`，N 从 1 起、小于现在的段。
- 筛查里和高血压有关的一项答了"是"、`conditions` 却记了没有高血压：提醒再确认。
- 复盘、菜单要写成 `.md`（`.txt` 也查红线）；别的不认识的文件给警告。
- **个人计划单**（`npm run course -- plan <档案目录>`，v4 阶段 3）：只生成**现在这一周**（`segments` 最后一项）的 `计划/第N段-第N周.md`，开头是声明和一行生成标记 `<!-- 养夏计划单 段=N 周=N 开始=日期 模板=版本 进度=日期/条数 -->`（进度是最后一次改动的日期和进度日志的条数，同一天又改了也分得出来）；内容全部来自训练单、规则参数和档案——每天能导出的动作（组数、次数或秒数、休息，动作写中文名）、照成品做的项、本周不做和可以加的、有氧做稳态还是间歇（按这一轮第 2 周的稳态自查 `steadyCheck`、"高血压没问过医生"；写在有氧那一项同一行）、每日习惯的达标线和习惯目标、下次评估和筛查到期的日期。档案目录先过检查、医生同意有效才生成。`profile check` 的核对：
  - 没有生成标记、文件名和标记对不上、标记写的是还没到的周、标记的段 / 周 / 开始日期不是 `segments` 里真有的那一项：错误；
  - 以前几段、以前几周的单子：截到标记的那一项、用生成时的进度（进度日志的前几条）重新生成，逐字比对；对不上（手改过，或者模板、条件、复盘、筛查日期后来变了）就是错误——以前几周的单子不用留，删掉。进度后来改了、周不是正好 7 天、重复过一周都不影响；
  - 现在这一周的单子：和按现在的档案生成的一样就通过。这一周重新开始过（标记的开始日期不是现在这一项的）、模板版本和生成时不一样：错误，重新生成；进度在生成之后改过——和按生成时的进度生成的一样、之后没往下调过的只提醒重新生成，往下调过的（旧单子比现在重）和其余对不上的都是错误。
- **声明**（目前没有专业人员审核）：`计划/`、`菜单/`、`复盘/` 下的 `.md`（含月度总结）开头要写一行 `> 本计划由养夏计划模板生成，未经专业审核，不是医学建议，不能替代医生的判断。`，缺了报错；`历史/` 下以前的不查。
- **评估**（第六节）：第一段之前要有入门评估；每段练完第 4 周、开下一段之前要有段末评估，下一段的段型、习惯目标照重算的结论；稳定期练完第 12 周要有周期末评估，下一段（下一周期还是回起始期）照重算的结论——结论是回起始期的，换不换成品段型都照结论；进稳定期的两条路、段的阶段和成品一致、稳定期里满 40 岁（新的一轮按这一轮第 1 周第一次出现那天算）、断了超过 56 天（最近一次，和稳定期中间断过又接着练的）都在这里核对；俯卧撑测试的级要是阶梯里有的级；"先看医生"之后要有看完医生回来的触发评估；换成品要有跨段或换场地的触发评估（带新成品入门的项目）；中途重来要有 `restart` 和对应的触发评估；每段开始那天推算的年龄段、学段要和成品、`stage` 对得上，满 65 岁当月起就要换版；筛查超过 365 天；65 岁以上摔倒以后要重做筛查；断了 5 天以上提醒半量、28 天以上要先做触发评估（最后一次训练按练习记录和周复盘里较晚的算）；13–17 岁连着两周疼提醒告诉家长、看医生。

Claude Code 每轮结束时，有改动的档案目录会自动跑一遍（`profiles/` 不进 git，按文件修改时间判断）。

## 四、练习记录

编排器练完导出，周复盘读它：

- 练的是哪个课程、开始和结束时间。
- 每个动作计划几组、完成几组、有没有跳过。完成组数只数实际播完"本组完成"那一拍的组（循环里是轮数）；用 → 跳过的不算，倒回去重练只算一次；不能多于计划组数。规则在核心库 `session.ts`，编排器和测试共用。
- 主观感受：轻松、正好、吃力。
- `edited`：练的课程在编排器里手动改过，和成品原文可能不一致；周复盘不按这份记录加量。
- `symptoms`：疼痛、头晕、胸痛胸闷。任何一项为 true，下周不加量，按成品"疼了怎么办"处理，必要时建议就医。
- 每个动作可选三项（编排器练习记录表单"每个动作"里填）：
  - `feel`：找级用的感受，照成品原话三选一："做不到下限或后面几下变形""能做到下限，最后两下有点难""做到上限还很轻松"；
  - `spare`：健身房，做完还能做几下（第 2 周调重量的依据）；
  - `reverted`：升级后做不到，当场退回原来那一级。

## 五、复盘数据

周复盘写 `.md` 的同时写同名的 `.json`（`yangxia.review/1`），数字照使用者说的填：

- `start`、`week`：这一周（`segments` 里那一项）的开始日期和周次（起始期 1–4，稳定期 1–12）；
- `trainings`：这一周练了几次（健身房、65 岁以上的平衡动作没有完整的练习记录，以这个数为准；不能少于练习记录数）；`checkinDays`：每日打卡达标天数；
- `symptoms`：这一周有没有疼痛、头晕、胸闷；
- `moves`：逐个动作的表现 `{ move, allAtTop, spare, allDone, easyTwice }`：每组是不是都做到区间上限、最后一组还剩几次余力；可选：每组是不是都做满当前次数（加次数要）、是不是连着两次训练都轻松（65 岁以上加次数要）。升级、加次数拿紧挨着的上一周的复盘当依据。

- v4 阶段 2 起的可选字段（段末评估要用，缺了段末算不出来）：
  - `habits`：这一周每项打卡项达标几天 `{ 打卡项: 0–7 }`，打卡项照模板 `打卡.md`（成人 散步、冥想；13–17 岁 动够60分钟、按时上床；65 岁以上 散步、放松；6–12 岁 动够60分钟、按时上床、视屏少于2小时）；
  - `falls`、`nearFalls`、`dizzy`：65 岁以上这一周摔倒、差点摔倒、头晕几次；`sickOrMeds`：这一周有没有生病、换药（是就提示做触发评估）；`weightDrop`：体重有没有明显下降（是就提醒问医生，不记数字）；
  - `sickDays`：6–12 岁这一周生病几天；
  - `half`：这一周练过半量课（中断、生病回来的第一次），这份复盘不当加量依据。这一周的练习记录里有半量课，就必须写 `half: true`。
  - 写了 `dizzy`（头晕过）的，`symptoms` 必须是 true。`habits` 的键要是这份成品这一种段型的打卡项；`weightDrop` 只给 65 岁以上。
  - `steadyCheck`（v4 阶段 3）：每一轮第 2 周的稳态自查过没过（成品原话"做完能说完整句子、第二天不觉得累"），true / false。过了，这一轮第 3–4 周的有氧才写间歇；没过、没记都是稳态。
  - `weightDrop: true`：要重做安全筛查，"最近体重掉得明显"照实答（答"是"就要医生同意）；`sickOrMeds: true`：提醒做触发评估（身体变化）、重做筛查。
  - `weight`、`cardioMinutes`、`tired`（v4 阶段 4，只给这一周按减脂的人）：这一周称的体重（公斤一位小数，每周最多一次，这一周要是"记"）、中等强度有氧大约几分钟（升不升有氧台阶照它算）、练完有没有没力气（有的话这一轮剩下的时间吃回到保持）。

## 六、评估记录

`profiles/<代号>/评估/<日期>-<种类>.json`（`yangxia.assessment/1`，格式见 `contracts/assessment.schema.json`）。测试项、参数、"下一轮的方向"都来自模板规则层（`rules.json` 的 `assess`、`nextRound`、`habits`），**不新增测试项**：测的就是成品第〇章和月度总结里已有的测量。`npm run course -- assess <档案目录> <种类>` 列出要问、要测的项；加上记录文件就按规则重算结论、核对。

| 种类 | 什么时候 | 记什么 | 结论（代码重算） |
|---|---|---|---|
| 入门 | 建档时，第一段开始之前（最晚当天） | `base`（最近 3 个月每周几天力量练习，18–64 岁、13–17 岁；直接进稳定期的门槛之一，其余只记录）；`prereqs`（40–64 岁 `{checkup, bpOk}`，只记是 / 否）；`tests`（成品第〇章的测试）；`body`（档案选了"记"的 18–64 岁） | `needDoctor`（开工前提有"否"）、`bmi`、`bmiClass`（低体重 / 正常 / 超重 / 肥胖，切点取自模板官方参数） |
| 段末 | 每段第 4 周的复盘之后、下一段开始之前 | `segment`（第几段）；`tests`（月度总结要的复测）；`body`；65 岁以上 `weightDrop` | `result`（下一轮的方向那一条）、`next`（标准 / 减量 / 不开 / 重来）、`downgraded`（有不适，往上的降为原样）、`extras`、`habitTargets` |
| 周期末 | 稳定期第 12 周的复盘之后、下一段开始之前 | `segment`（刚练完的稳定期那一段）；`tests`（和段末一样的复测）；`body` | `result`（训练没达标 / 连续两个周期没达标 / 习惯没达标 / 达标）、`next`（`{ phase: 起始 / 稳定, type?, hold? }`） |
| 触发 | 跨段、满一年、身体变化、生病住院、生病、摔倒、换场地、中断、看完医生回来、回起始期（稳定期的人自己要求） | `reasons`；`doctorRestart`（医生建议从头来，是 / 否）；跨段、换场地写新成品 `product`，并带上新成品入门的全部项目（换了年龄段还要重新筛查，`screening.date` 不早于这次评估）；`doctorCleared`、`doctorDate`；`eventDate`（摔倒、生病住院那天，必填）；一份"摔倒"记了一周里的好几次摔倒的，`eventDates` 写每次的日期（`eventDate` 是最近那次，同一天摔两次写两份）；65 岁以上年度复评 `fallAssessDone`（必填，没做过提醒去做） | 换成品按入门核对 |

- 四周的数字由代码从周复盘数据算（`SEGMENT_COUNT`）：每个周次只取最后一份复盘，每周训练数不超过这一周排的次数；生病超过 7 天、摔倒、差点摔倒、头晕按整段加起来。
- 测试的写法：`{ id, level?, value, depth?, mode?, move?, hands?, done?, stopReason? }`，只能记规则层给这个测试列的字段；评估记录的顶层字段也只能是 schema 列的那些。65 岁以上的测试要 `companion: true`（家人在场），评估里记测的时候那一次医生同意（`doctorCleared`、`doctorDate` 不晚于评估日期，也不早于测之前最近一件要医生同意的事）；这一段摔倒、头晕过的，段末可以不测。有高血压或没确认的，靠墙静蹲最多 30 秒。
- 档案选了"记"体重腰围的：入门、换成品的触发评估要记身高、体重、腰围，段末要记体重、腰围。BMI 只看最近一次筛查以后称的体重（称的那天是"记"）——筛查以前的旧体重不拿来推翻后来的筛查答案，筛查以后量过的改成不记也照样核对。评估和复盘分开看：筛查以后最近一份评估量到 ≥ 28 而筛查"BMI ≥ 28"答"否"报错；比它新的周复盘称到的只提醒，下一次评估量的时候确认（一次周称重不停训练），不顶掉评估的报错；最近一次称的 < 18.5 提醒不选减脂。
- **6–17 岁的评估不能有身高、体重、腰围、BMI**；65 岁以上不记这些数字；"不记 / 停记"的人也不能有。BMI ≥ 28 而筛查"BMI ≥ 28"答了"否"，报错（见上一条）。
- 不记：身材照片、血压数值、体检结果。65 岁以上的跌倒风险自查只记是 / 否、秒数和测试条件，等级由命令算出、和答案一起存在记录里（下面一节）。
- 满 65 岁当月起按人的年龄：新的评估不能有身体数据，复盘的 `weightDrop` 可以记，复盘、菜单、评估备注按 65 岁以上的红线查，开始前要医生同意、摔倒后暂停平衡（成品还没换过来的那几天也一样；导出、计划单那几天本来就拦）。

### 65 岁以上的跌倒风险自查（`fallRisk`，v4 阶段 3c）

照模板椅子辅助版第〇章《跌倒风险自查》和规则层 `rules.json` 的 `fallRisk`（WS/T 887—2026 第 5 章的问法、测法、判定线；在家做的自查，**不是正式的跌倒风险评估**）。

| 字段 | 内容 |
|---|---|
| `fallRisk.askedOn` | 问卷做的日期 |
| `fallRisk.general` | `{ fell, unsteady, fear }`：`fell` 是 true / false；`unsteady`、`fear` 只问老人本人，说不清的写 `null` |
| `fallRisk.severity`、`fallRisk.frail` | 一般性有"是"或说不清时才问：`{ twoPlus, medical, helpUp, syncope }`、`{ fatigue, stairs, walk, illness, weightLoss }`，每项 true / false（疾病只记有没有 5 种或更多，不记病名；体重只记是 / 否） |
| `fallRisk.needsSupport`、`hardToStand` | 在家走路也要扶墙或用助行器、扶着椅子也很难自己站起来：true / false |
| `fallRisk.dizzy` | 经常头晕，或者站起来时眼前发黑：问卷时另外问（和安全筛查同一句话；换版时 40–64 岁的筛查没有这一项），true / false。以后重做筛查不改它，以前合规测过的步态不会因为后来的筛查变成错误 |
| `fallRisk.walk4m`、`tug` | 测了：`{ seconds（最多一位小数，往大里取）, cane, siteOk, testedOn }`，起立行走另有 `chairOk`（必填）；4 m 喊"开始"的同时按表，起立行走背离开椅背时按表（附录 D.4）。客观原因没测成：`{ result: "没测成", reason }`（场地不够、椅子不合要求、家人不在、本人不想测、中途停下——中途停下的写 `stopReason`：头晕 / 腿软 / 身体晃）；按规则不测：`{ result: "按规则不测", reason }`（跌倒过、高风险、走路要扶、站起困难、经常头晕） |
| `fallRiskSeen`（评估记录顶层） | 医生看过这份自查结果（这份记录或之后的"看完医生回来"）；同一份记录的 `doctorCleared`、`doctorDate` 就是拿这份结果换来的医生同意 |
| `official`（评估记录顶层） | 医生或社区做的正式跌倒风险评估 `{ date, afterFall（是不是在最近一次摔倒之后做的）, level?（低 / 中 / 高） }`，日期不晚于这份记录。只有和自查记在同一份记录里、前后 90 天以内的等级才并进这份自查的结论；记在之后"看完医生回来"里的，只用来核对"跌倒过要先做正式评估"，不改等级 |
| `conclusion.fallRisk` | 命令重算：`level`（低 / 中 / 高 / 未定）、`worst`、`effective`（合了正式评估）、`gaitOfficial`、`gaitMargin`、`gaitIncomplete`、`doctorFirst`、`officialNeeded`、`reassessBy` |

- **等级**照标准 5.1.4、5.2.1 算，只用得到的答案和测出来的结果。一般性 3 问都"否"的，标准到问卷就结束、是低风险——这份计划照样测步态，测出来超线、没测成都不改等级，超线的 6 个月再查。一般性有"是"或说不清的：有说不清的、步态没测的，当阳性、当阴性各算一遍，不一样就是"未定"，处理照可能的最高一级（`worst`）。4 m 用时 ≥ 4.5 秒、起立行走 ≥ 14 秒记"按留余量的线阳性"（`gaitMargin`，只定多久再查，不改等级）。同一份记录里有前后 90 天以内的正式评估等级：自查未定的照正式的，都定得了的取高的；正式评估说高风险的，之后不在家测步态。
- **什么时候要做**（规则层生效日期之后的记录；入门要第一段也在生效日期之前开始才免）：65 岁以上入门、换到 65 岁以上版的跨段、满一年、摔倒、生病住院、身体变化、跌倒自查到期。触发评估要**重新做一次问卷**：摔倒、生病住院、身体变化的问卷不早于 `eventDate`；不能和更早写的记录里的问卷一模一样（照抄，只报后写的那份）。档案里记着的最近一次摔倒（触发评估、复盘的 `falls`），要有一份问卷在它之后（同一天的要说跌倒过），没有就报错：做"摔倒"的触发评估。复盘的 `falls` 比这一周"摔倒"触发评估记的次数多，多出来的按这一周最后一天算——一周摔了几次，一份触发评估把每次的日期写进 `eventDates`。
- **先问医生**：一年内**每一份**自查分别核对（新问卷盖不掉旧问卷的要求）。过去 12 个月跌倒过、或者高风险的（`doctorFirst`）：要有一份写了 `fallRiskSeen: true` 的记录（这份或之后的），它的 `doctorCleared`、`doctorDate` 在问卷之后 30 天以内；之前导不出课程、生成不了计划单。之后因为别的事再看医生、档案的 `doctorDate` 往后改，不影响这一条。一年内任何一份说跌倒过的（`officialNeeded`），还要有摔倒之后的正式评估（`official.afterFall: true`、日期不早于档案里已知的最近一次摔倒）。
- **多久再查**：中风险、按余量阳性、未定而可能最高是中：问卷后 182 天（到期没查报错）；其余每年一次——从最近一份问卷算 365 天，到期没查报错（不跟着别的原因重做的筛查往后挪）；高风险问卷后 30 天起没有新的正式评估，提醒随访。计划单的"下次评估"写这个日期。
- **和档案对得上**：档案里一年内有摔倒而第 1 问答"否"、摔倒 2 次以上而"2 次以上"答"否"（摔倒一次算一次：同一周复盘记的和触发评估记的取多的那个，不重复数；问卷那天的摔倒分不清先后，说没跌倒过的不追溯、之后要有新问卷）、第 1 问"否"而严重程度有"是"、跌倒过或在家走路要扶而问卷之前做的筛查"最近一年摔倒过……走路要扶东西"答"否"、问卷之前做的筛查和 `dizzy` 对不上、测步态那天有效的筛查说经常头晕却记了秒数、不在家测的人记了秒数、步态不是家人在场或在医生同意之前测的，都报错；前一份说跌倒过、不到一年的后一份说没有，问卷之后 7 天以内重做的筛查对头晕答得不一样，衰弱的体重下降和筛查对不上，步态中途头晕停下，给警告。
- **周期末结论**（模板 `稳定期.md` 的"下一周期"，有序，从上往下取第一条）：12 周的数字由代码从周复盘数据算（每个周次只取最后一份、每周训练数不超过排的次数；成人散步、冥想，13–17 岁动够 60 分钟、按时上床，按"每周达标 ≥ 5 天"数达标的周数）。表按成品家族各一张（`nextCycle[].products`），达标线是那个家族登记的（"习惯达标周数"写一个数是每项都一样，也可以按打卡项写"散步 9、放松 7"）。成人：训练 < 36 练 → 回起始期减量段（`CYCLE_LOW`）；散步或冥想达标 < 9 周而且上一个周期也没达标 → 回起始期标准段（`CYCLE_FAIL_TWICE`）；散步或冥想达标 < 9 周 → 下一周期、第一轮不升级（`CYCLE_HOLD`，`next.hold`）；其余达标，下一周期进度接着用（`CYCLE_PASS`）。13–17 岁同样四条，训练线是 24 练、两项习惯各 9 周（`CYCLE_PASS_YOUTH`）。65 岁以上 24 练、散步 9 周、放松 7 周（每一轮第 2–4 周，共 9 周，`CYCLE_PASS_SENIOR`），前面多一条第 0 行：最后一轮摔倒、差点摔倒、头晕（含周期末坐站停下的原因是头晕）→ 先看医生、不开；周期末以后看医生做触发评估"看完医生回来"，`doctorRestart: false` 跳过这一行照后面几条，`true`（或没写，没写报错）回起始期标准段。不适不计入周期达标。
- **65 岁以上稳定期一轮里摔倒、差点摔倒、头晕**（`A65_STABLE_FALL`）：第 4、8 周练完不开下一轮，轮末以后看医生、做"看完医生回来"并写 `doctorRestart`；`true` 或没写回起始期标准段第 1 周，`false` 接着下一轮；加项都清零。生病住院（触发评估"生病住院"）、断了超过 28 天（`回起始期的中断天数`）也回起始期第 1 周：周期中途的回标准段；第 12 周住院的，段型照周期末结论（"训练没达标"回减量段），周期末那条也认"生病住院"当回起始期的理由。回起始期是回同一家族的起始期成品，进度接着用。

### 稳定期的目标（保持、减脂、增肌，v4 阶段 4）

照稳定期成品《稳定期说明》的《目标：保持、减脂、增肌》和规则层 `rules.json` 的 `goals`（`content/rules/目标.md`）。目标只改有氧、吃和周期末，力量课程不变；有氧不导出，这一周做多少分钟由命令算、写在计划单和导出提示里。

| 字段 | 内容 |
|---|---|
| 评估 `goal` | 这个周期选的目标，写在开周期的那份——**按位置认**：上一段是稳定期的，它的周期末；上一段是起始期的，它的段末；建档直接进入的，入门。档案这一段第 1 周的 `goal` 要和它一致，选减脂、增肌的这一份要有 `eatingCheck: "问过"`，不能拿更早的一份顶替 |
| 评估 `eatingCheck` | 选减脂、增肌前照第八章开头原话问一次进食困扰：答了没有写 `问过`；答了有只写 `只能保持`（不记答案），这个周期只能保持 |
| 评估 `goalConsent` | BMI 不到 18.5 的人选增肌：医生或营养师同意的那天 `{ date }` |
| 周期末 `conclusion.goals` | 命令重算：下一周期能选的目标（接着开稳定期的才有；保持的周期按这份记录量的 BMI、腰围过一遍那张表）。换到有目标规则的模板以前写的周期末记录没有 `goals`，只给警告，用 `course assess` 重算一次补上 |

- **谁能选**（`goalGate`）：先过——稳定期、18–64 岁、这 12 周里不满 40 / 65 岁（按人的年龄）；那一天"记"体重腰围；进食困扰没有；周期开始前 28 天以内有一份评估量了体重和腰围（身高用入门的）。再看 BMI 和腰围（不问性别，减脂按 90 cm、增肌按 85 cm）：BMI < 18.5 保持或增肌（增肌要 `goalConsent`）；18.5–23.9 腰围 < 85 保持或增肌、85–89 只保持、≥ 90 保持或减脂；24.0–27.9 保持或减脂；≥ 28 只保持（减脂等阶段 5）。连着两个减脂周期以后、停记以后，先完整练一个保持周期（12 周、每周都是保持）才能再选减脂。直接进稳定期的人第 1 轮按保持，选的目标第 2 轮起生效。
- **减脂的有氧台阶**（`cutCardio`）：每周合计中等强度 100 → 150 → 200 → 250 分钟（训练里的有氧算进去）；连着两周做到这一档、没有疼痛头晕胸闷，而且这一档练满 2 周（40–64 岁 4 周）才升；这一轮有不适不升，下一轮第 1 周没有不适以后才接着升；"中断"触发评估以后回第一档；紧挨着上一个减脂周期的接着上次做到的那一档（最后一周没做到就退一档）；上一周期周期末"第 1 轮不升级"的，第 1 轮有氧也不升档。有高血压（或没确认）、筛查有"是"的要有有效的 `cardioClear`，没有就照保持的量。
- **吃**：减脂比保持少约 300 kcal（肉、油、主食；女性主食不减），不低于计划单上按身高体重年龄估的基础代谢（男、女两栏），全天低于 1200 先问医生；这一轮有过不适或 `tired` 的，这一轮剩下的时间吃回到保持。增肌比保持多约 200 kcal（主食）。筛查第 3 项（糖尿病、肾病、痛风或高尿酸、高血脂）答"是"的，吃照医生的意见。
- **中途退回保持**（`goalIssues` 拦）：那一周起不记或停记了（改动那一周起）；减脂开始生效的第 3 周以后（直接进入的从第 2 轮算）连着 4 次称重、按天数折算平均每周掉超过 1 kg，或者称的体重 BMI 不到 18.5（复盘发现的下一周起）；增肌在周期里的评估量到 BMI 24 或腰围 85。
- **周期末**（`cycleGoals`）：减脂——因为停记、掉太快、BMI 太低退回过的、BMI < 24 而且腰围 < 90 的、连着两个减脂周期的，下一周期只能保持；其余能接着减脂或保持。增肌——BMI ≥ 24 或腰围 ≥ 85、12 周体重涨超过 3% 或腰围涨 2 cm 以上的，下一周期只能保持；其余能接着增肌或保持。保持的周期，下一周期照"谁能选"。
- 菜单只写档案主人自己那一份（减脂肉少盛一些、主食少半个馒头，女性只写肉；增肌主食多半个到一个馒头），不写千卡、减脂、减肥，不写别人的目标。
