# 养夏 v4 方案：结构化模板与分阶段计划（r4，三轮独立审查通过；阶段 1 已实施）

> **用户需求**（原话摘要，2026-11-08）：
> - 模板最初只有一个月计划，只按年龄分，没有区分人群：肥胖、基础病和慢性病；也没有区分减重和增肌。
> - 要区分新手和有一定锻炼基础的人，训练和饮食需求不同；训练阶段分起始阶段和稳定发展阶段。
> - 起始阶段每过一段时间做一次评估来调整方案；稳定阶段也要随着年龄增长评估调整。
> - 先判断要不要重构、结构化模板；"开始全面规划设计，独立审查通过后开工"。
>
> **结论**：先把模板里给程序用的部分（训练处方、个人进度规则、评估、阶段和人群规则）结构化，起始期成品正文不变；再在新结构上分阶段加维度。
> **原则**：沿用 v3——只在模板规则之内定制；官方数字先核对原文；不做疾病的运动处方；每阶段有可检验的验收标准，单独提交。
> **r2–r4 改了什么**：见第十二节审查记录。

## 一、现在的样子和问题

| 部分 | 现在 | 问题 |
|---|---|---|
| 成品 | 10 份：年龄段 × 场地（8 份训练 + 6–12 岁家长版 + 全家餐饮），每份 4 周 | 只有一个月；第 4 周后只有"下一轮的方向"（含减量版：每周 3 练、B+C 合并日） |
| 人群 | 只按年龄段分；肥胖、慢性病只在筛查里，结论是"先问医生"；医生同意后用的是完整计划。正文里另有按身体情况、家庭条件分的写法（有高血压不做派克、骨质疏松换动作、家里没有别人不做 9 号、没地方跳换踏步） | 这些条件没有对应的数据，程序不知道该给谁哪个版本 |
| 目标 | "减脂 −300 千卡 / 增肌 +200 千卡"（设计值 `NEXT_ROUND`）只在"下一轮的方向"里各一句 | 训练和饮食都没有按目标区分 |
| 训练基础 | 第 1 周按新手写（只学动作、找难度级） | 有基础的人没有对应的起点 |
| 个人进度 | 难度级第 1–2 周"找级"、因人而异；次数在区间内逐步加（65 岁以上"每组多做 1–2 次、不超过上限"）；40–64 岁"这一轮不升级" | 这些只写在正文里；课程检查只认区间下限，进度没有记录 |
| 评估 | 每轮结束有"月度总结"（填表、选下一轮方向） | 没有正式的测试项和判定标准；年龄跨段、长时间中断没有规则 |
| 结构 | 处方写在正文和表格里；成人 6 份靠 279 个"年龄段 / 场地"版本块区分 | 维度从 2 个变 6 个，版本块会组合爆炸 |
| 课程检查 | 从成品正文里摘原文、找数字（`check.ts`） | 不核对训练日、不核对一天的动作齐不齐；一个动作有多套处方后靠读文字守不住 |

## 二、需求整理：维度和它们放在哪里

| 维度 | 取值 | 放在哪里 | 由什么决定 |
|---|---|---|---|
| 年龄段 | a06、a13、a18、a40、a65 | 成品（不变） | 入口问卷；之后按出生年月或学段推算，跨段时触发评估（5.4） |
| 场地 | gym、home、bw、play、chair | 成品（不变） | 入口问卷 |
| 适用条件 | 有高血压、骨质疏松、家里没有别人、没有跳跃场地…… | 训练单的"适用条件"列 | 档案记录（第十一节第 1 条已定：记）；没确认时导出最保守的版本 |
| 个人进度 | 每个动作现在的难度级、次数，健身房还有重量 | 档案 | 只能由周复盘按成品规则改，代码核对 |
| 训练基础 | 新手、有基础 | 起始难度级 | 入门评估（问题 + 次最大测试），不靠自评；有基础的人同样走 4 周起始期，只是从更高的难度级起步（4.6） |
| 阶段 | 起始期、稳定发展期 | 成品类型 | 起始期段末评估达标才进入稳定期 |
| 目标 | 保持、减脂、增肌 | 稳定期的模块 | 只给 18–64 岁成年人；65 岁以上只有保持；6–17 岁不分目标 |
| 安全人群 | 超重、肥胖、慢性病（医生同意）、不覆盖 | 筛查结论 + 附册 | 筛查答案 + 医生同意 + 入门评估的 BMI 分档 |
| 评估 | 入门、段末、周期末、触发 | 规则层 | 时间到了，或者跨段、身体变化、中断 |

**不按维度拆成品**：成品仍按"阶段 × 年龄段 × 场地"一行一份（和现在的构建方式一致），每个人这一周做什么，从结构化数据和档案生成"个人计划单"。

## 三、总体设计

### 3.1 文档体系

| 类型 | 是什么 | 怎么构建 |
|---|---|---|
| 起始期成品 | 现有 10 份，正文不变（阶段 2 起加"评估"一节） | 不变 |
| 稳定期成品 | 成人：18–39、40–64 × 健身房 / 居家 / 徒手，6 份；13–17 岁、65 岁以上各 1 份（阶段 6） | 和起始期一样：`products.md` 一行一份，读者文件夹 `content/adult-stable/` 共用 + 版本块；**处方表由训练单生成**，只有一处来源 |
| 附册 | 《超重与肥胖》（只给 18–64 岁）、《慢性病饮食参考（医生同意后）》（18–64 岁版、65 岁以上版） | 一行一份，带年龄段，按年龄段过红线 |
| 个人计划单 | 主仓库按档案生成，一页：这一周每天练什么、每个动作的级和次数、吃饭的几条要点、下次评估日期；导不出的项写"照成品第几章做" | 不提交 |

`products.md` 加一列"类型"（起始 / 稳定 / 附册），manifest 的 `products[]` 同步。

### 3.2 使用者路径

```
建档（onboard）：入口问卷 → 安全筛查 → 入门评估
   │  不覆盖 / 医生没同意 → 不出计划
   ├─ 新手 ─────────────→ 起始期（4 周一段），从起始级开始
   └─ 有基础（测试达线）→ 起始期（4 周一段），从入门评估定的难度级开始（4.6）
起始期 ── 段末评估 ─┬─ 没达标 / 有不适 → 再来一段（按成品"下一轮的方向"：原样或减量版）
                   └─ 达标 → 稳定期（档案的 product 换成稳定期成品）
稳定期（12 周一个周期）── 周期末评估 → 调整目标、下一周期起点；必要时退回起始期
随时触发：年龄或学段跨段 · 身体情况变化 · 中断（按成品原文处理，见 5.5）· 距上次筛查满一年
```

- 6–12 岁、13–17 岁、65 岁以上在阶段 6 之前**没有稳定期**：起始期达标后照成品"下一轮的方向"再跑一段，段末照样评估。这是现状，写明不算断点。

### 3.3 三层结构

| 层 | 内容 | 写法 |
|---|---|---|
| 说明层 | 安全须知、动作做法、常见错误、为什么这么练、饮食解释 | Markdown 正文（起始期不变），版本块只管年龄段和场地 |
| 处方层 | 训练单：每个训练日的动作、组数、次数区间、每一级的变式和节奏、休息、适用条件、取舍方式、能不能导出 | `content/plans/*.md` 表格（Python 标准库能读） |
| 规则层 | **只放参数**：进度规则的数字（每次加几次、哪几周能升级）、评估测试项和判定线、阶段转换的门槛、目标模块参数、人群和条件表、中断处理 | `content/rules/*.md` 表格。**判断逻辑写在主仓库核心库**，每条配"拦下 / 放行"用例；不在 Markdown 里另造条件语法 |

### 3.4 发布物

- `dist/data/plans.json`（训练单）、`dist/data/rules.json`（规则参数）；manifest 加 `data` 一项列出文件和格式号（`yangxia.plans/1`、`yangxia.rules/1`）。新增字段，manifest 仍是 `yangxia.manifest/1`；主仓库 `contracts/templates.json` 写明需要的数据文件，缺了就提示"先更新模板"。
- 主仓库的离线样例同步加训练单和规则的节选（`make-fixtures`），主仓库测试不依赖还没合并的模板分支。

## 四、处方层

### 4.1 训练单表格

| 列 | 例子 | 说明 |
|---|---|---|
| 成品 | 18-39岁-徒手版 | |
| 段型 | 标准 / 减量 | 起始期的标准段、"下一轮的方向"里的减量版；格式留出扩展（以后可以加别的段型） |
| 周 | 1 / 2 / 3–4 | 起始期 1–4；稳定期 1–12 |
| 日 | A | 训练日（减量版的"B+C 合并"是单独一个日） |
| 序 | 1 | |
| 动作 | squat | 动作索引 ID；有阶梯的写阶梯组 ID |
| 组 | 2 | 递进表本周那一格 |
| 次数区间 | 15–20 次 / 30–60 秒 | 存区间，不预先取值 |
| 次数来源 | 进度 / 周表 | "进度"：实际次数来自档案进度（4.3）；"周表"：次数由本周那一行定（健身房第 3 周 12 次降到 10 次同时加重），进度只管重量 |
| 级 | 第 1–3 级 | 允许的难度级；每一级的变式、节奏、出处在"阶梯表"里 |
| 休息 | 90 | 区间写上限 |
| 适用条件 | 无 / 非高血压 / 有人在旁边 | 条件名和"没确认时用哪个版本"在规则层逐个写明（5.4） |
| 取舍 | 必做 / 本周不做 / 超时按顺序砍(3) / 有富余才加 / 轮换(每次·A6、A7) / 按器材选一个(C1) | 五种取舍分开写，见 4.4 |
| 导出 | 可导出 / 照成品做：原因 | 原因如：交替动作、65 岁以上按"次"的平衡动作、有氧和单车、原文有歧义待澄清 |
| 来源 | 表格：递进表第 2 行 / 原句："…"（成品 · 小节） | 数字从哪里来：表格的位置，或者文字处方的原句；**原句要标明出自哪份成品的哪一小节** |
| 解读 | （原句时必填）"各 3 组"指第 2 周起的 3 组 | 从文字处方读出的意思，人工写、人工核 |

**阶梯表**（每个阶梯组一张）：级、动作 ID、节奏（下放、停、发力各几秒）、什么时候能升、出处。

### 4.2 数据和正文的一致性：核对放在模板仓库

第一轮审查实测"每行生成课程、跑原文核对"证明不了一致；第二轮审查确认"从正文独立推出每天的清单"只对表格做得到。所以按正文的写法分两种核对：

1. **表格写的处方，写解析程序独立推出，和训练单逐一比对**：取舍表、递进表、65 岁以上训练单（一列一周）、循环清单、健身房训练表的编号行。读不出来的格子构建报错，不猜。
2. **文字写的处方**（健身房"侧平举或绳索下压"这类取舍、A5–A7 写在"做法"里的次数、13–17 岁"不做臀桥"、核心"每周轮换"、减量版的一句话）：训练单的"来源"记下原句，"解读"写人工的理解。构建核对**原句仍然逐字在成品里**；正文一改原句就报错，逼人重新核对解读。
   - 原句要在它标明的那一小节里逐字出现，挪到别的训练日小节也报错。
   - **漏转也要报**：训练相关章节（训练框架、动作库、下一轮的方向、训练单）里"数字 + 组、次、秒、轮"和含"不做、换成、砍、轮换"的句子（呼吸节奏那一行归阶梯表管，不在这里查），要么被训练单引用，要么登记进 `content/plans/不影响训练单.md`（写明为什么不影响，如"讲动作要领"），两样都不是就构建报错。以后正文新加了处方句，构建会逼人处理。
   - **原文有歧义的**（如减量版"各 3 组"算不算第 1 周、健身房"A / B / C 轮换"的意思）：阶段 1 一律标"照成品做：原文有歧义待澄清"，不导出；整理成"正文歧义清单"交给你，澄清要改正文，按模板维护流程另行处理。
3. **核对放在模板仓库**：`check.py` 做上面两种核对；另外核对 `dist/` 是最新构建（在内存里重新构建一遍，比 `.md`、`manifest.json`、`dist/data/`，不一致就报"改了 content 没有重新构建"；示意图 SVG 有浮点误差、PDF 要 playwright 才能生成，这两样不比）。`tpl.py all`、每轮结束的检查都会跑；模板仓库的提交前检查在 `content/`、`tools/` 有改动时跑 `tpl.py check`，并且要求 `content/`、`tools/`、`dist/` 没有未暂存的改动（否则查的是工作区、提交的是暂存区，两者可能不一致）。模板仓库仍不依赖主仓库。
4. **主仓库的原文核对只核对"标准段、不带适用条件、起始级、区间下限"的课程**（模板在才跑，离线样例常跑）。条件变体（如高血压版"多做 1 组俯卧撑"）、减量段、更高的级、带个人进度的课程，原文核对都会误拦，只走训练单 + 进度规则的核对；它们和正文的一致由第 1、2 条在模板仓库保证。

### 4.3 个人进度：难度级、次数、重量

- **档案记每个动作的进度**：难度级、每组次数（节奏跟着级走）；健身房再记重量（器械几片、哑铃几公斤，只是器械重量）。建档时：次数取区间下限；级见 4.6；重量按成品"起始重量怎么定"由使用者试出后记录。
- **进度从哪里改**（照正文的做法，不只在周复盘）：
  - **找级（第 1–2 周）**：正文是"这次练完、下次训练就调"。练习记录每个动作加一项可选的感受，选项照正文原话："做不到下限或后面几下变形"（降一级）、"能做到下限，最后两下有点难"（就是这一级）、"做到上限还很轻松"（下次升一级）；下一次导出时照上一次的感受调一级，只在第 1–2 周。**找级的升降不受下面"次数先到上限"那条限制。**
  - **健身房调重量（第 1–2 周）**：正文是"还能做 6 下以上就加一档"，也是两次训练之间调。练习记录的感受对健身房动作记"还能做几下"，下一次导出时照正文加一档或不变。
  - **升级做不到当场退回**：练习记录里记"退回"，下一次导出就用原来那一级。
  - **加次数、升级、加重**：周复盘时改，写进复盘数据。
- **代码核对**：
  - 找级以外的升级：**档案里这个动作的次数已经到区间上限**（查档案，不靠口述），并且复盘里报告最后一组还有余力；升级后次数回到区间下限；
  - 一次只改一样：升级、加次数、加重量、加背包不同时发生（"次数来源 = 周表"的行，次数随周表变，不算一次改动）；
  - 次数不超过区间上限；**超过上限的**只有成品明文写了、而且记录了医生同意的才行（如 65 岁以上下一轮"坐站起加到 12 次或加第 3 组，先问医生"）；
  - 只在成品允许的周、允许的级：18–39 岁第 4 周达标的升一级；40–64 岁这一轮不升级、**下一轮从第 1 周起可以升**（照 `adult/next.md` 原文）；健身房第 3 周加重、下一轮双进阶（设计值 `GYM_DB_STEP`、`NEXT_DOUBLE_PROG_GYM`）；训练单"级"列之外的级（如"下一轮才用"的保加利亚分腿蹲）不能用；
  - 每次加几次：成品写了的照成品（65 岁以上每组多 1–2 次）；成人版没写的，登记为设计值；
  - 这一段里（或者上一周）有疼痛、头晕、胸闷记录：不加、不升（可以降）；有不适的那一周，同一段的下一周周次不往上走。
- **导出课程**：组数、休息来自训练单；次数按"次数来源"取进度或周表；级、节奏、重量来自档案进度。agent 只选哪一天，不填数字。

### 4.4 取舍的五种写法

| 写法 | 例子（原文） | 导出时 |
|---|---|---|
| 本周不做 | 18–39 徒手第 3–4 周 A 日"不做提踵" | 不导出 |
| 超时按顺序砍 | "C 日超时再砍超人式""从最后一个动作往前砍" | 默认导出；个人计划单注明"时间不够先砍它" |
| 有富余才加 | 健身房"A5 有富余再加" | 默认不导出；注明"有时间可以加" |
| 轮换 | 健身房"A6、A7 每次换一个"；13–17 岁核心"每周轮换" | 按档案记录的上次位置轮换；轮换单位（每次 / 每周）写在训练单里 |
| 按器材选一个 | 徒手版 C1 二选一、13–17 岁 C1 三选一（桌下划船要家长压住桌子） | 按档案记录的选择；选择受适用条件约束（如"有家长在旁边"） |

验收：每一天"可导出的 + 照成品做的"合起来，等于 4.2 核对出的清单。

### 4.5 稳定期：12 周一个周期

- 周期分三块：第 1–4 周适应、第 5–8 周递进、第 9–12 周巩固；周期末评估。块的划分、组数和强度是**设计值**，登记理由。
- 稳定期是新写的内容：训练单是唯一来源，成品里的处方表由训练单生成。
- 目标模块只改几样，其余共用：

| 目标 | 训练 | 有氧 | 饮食 |
|---|---|---|---|
| 保持 | 按阶梯升级为主 | 官方推荐量（`PA_ADULT_AEROBIC`） | 均衡，照膳食指南 |
| 减脂 | 力量保持（防掉肌肉） | 往推荐量上限走 | 热量缺口用设计值（见第十一节）；官方 `LOSS_REF`（每天少 500–1000 千卡）是给肥胖人群减重的区间，只作上限参考 |
| 增肌 | 组数和难度递进 | 保持下限 | 蛋白质按官方膳食营养素参考摄入量（2023 版）核对后的数字；不推荐补剂 |

- **筛查第 3 项（糖尿病、肾病、痛风或高尿酸、高血脂）答"是"的**：所有个人化的饮食部分都不出——起始期饮食建议（成品写明"本计划蛋白质偏高"）、减脂、增肌、排菜单，一律"饮食照医生的意见"；训练部分照常（医生同意后）。
- 65 岁以上的稳定期只有"保持"：力量照官方老年人身体活动建议（`PA_OLDER_CN`、`PA_ADULT_STRENGTH`），蛋白质照一般老年人推荐量（`PROTEIN_RNI_65`，**用前回到膳食营养素参考摄入量原文核对**，现在的依据是肌少症指南转引）。不用肌少症指南的参数。
- 13–17 岁的稳定期只有"保持"，不谈体重和热量。
- 40–64 岁：起始期"这一轮不升级"；推迟的升级照原文"下一轮从第 1 周起就可以开始"，稳定期第一个周期起照常升级。

### 4.6 有基础的人从哪里开始

- **不另设段型**：有基础的人同样走 4 周起始期（作息、饮食的每日习惯也要从这里建立），区别只是**难度级的起点**。正文里"第 1 周找级、第 2 周稳态 20 分钟自查后第 3 周才上间歇"这些安全前提全部保留。
- **起点受"这一轮允许用哪几级"限制**：只能在训练单本周"级"列允许的范围里起步。40–64 岁版第 4 周的进阶难度和额外负重这一轮不用；保加利亚分腿蹲这类"下一轮才用"的不用；65 岁以上的训练单按周逐步减少扶的手，**不跳着用后面几周的扶法**（65 岁以上不设更高的起点）。
- **谁说了算**：入门评估只给第 1 周的起步建议；第 1–2 周照正文人人找级，**找级的结果为准**。
- 如实说明：找级本来人人都做，所以有基础的人在起始期和新手差别不大，真正的区别在稳定期（起点更高、递进更快）。这样不用写新的处方内容，段型留了扩展。是否另设快速段，交你决定（第十一节）。

## 五、规则层

### 5.1 评估

| 种类 | 什么时候 | 测什么 | 决定什么 |
|---|---|---|---|
| 入门评估 | 建档时 | 最近 3 个月训练频率；按年龄段的次最大测试；18–64 岁另测身高、体重、腰围（如果你决定记，第十一节） | 新手 / 有基础和起步难度级；成年人 BMI 分档 |
| 起始期段末 | 每 4 周（替代"月度总结"，原表格保留） | 训练完成数（现有成功线）、打卡达标天数、动作进度、不适记录 | 再来一段（原样或减量），或进入稳定期 |
| 稳定期周期末 | 每 12 周 | 同上，加目标相关指标（只限 18–64 岁：减脂看腰围和体重趋势，增肌看进度） | 下一周期的目标和起点、要不要退回起始期 |
| 触发评估 | 跨段；身体情况变化；中断；距上次筛查满一年 | 重做筛查；跨段重新选成品 | 换成品、先问医生、按中断规则处理 |

**测试只用次最大测试，不做极限测试**，和现有正文一致（不练到力竭；13–17 岁"不测自己最多能做几个"；有高血压的平板每组不超过 30–45 秒）：

- 形式：规定组数、规定次数下能不能做完、动作质量过不过关、做完后还剩几次的余力；
- 每个测试项登记适用年龄段，名称和说明按该年龄段的红线检查（代码拦，示意图同样）；6–12 岁、13–17 岁不用体重、BMI、等级、排名；65 岁以上不用闭眼、跳跃类项目（官方体测里有的也不用）；
- 判定线优先用官方标准里能对上的部分（实施前补调研、核对原文），对不上的登记为设计值；
- 65 岁以上的测试必须在医生同意之后、有人在旁边时做。

**称体重、量腰围**（只限 18–64 岁）：频率上限和停下来的条件（例如出现节食、焦虑）写成设计值；记不记、多久记一次待你决定（第十一节）。

### 5.2 阶段转换

| 从 | 到 | 门槛（参数在规则层，判断在核心库） |
|---|---|---|
| 起始期 | 起始期（再来一段） | 段末没达标，或这一段有不适；按成品"下一轮的方向"选原样或减量 |
| 起始期 | 稳定期 | 段末达标（成功线 + 动作进度 + 这一段没有不适） |
| 稳定期 | 稳定期下一周期 | 周期末评估完成 |
| 稳定期 | 起始期 | 中断按 5.5；**连续两个周期末评估都没达标**（"退步"的定义，设计值）；身体变化后医生建议从头 |
| 任何 | 停止出计划 | 筛查结论变成"先问医生"（医生没同意）或"不覆盖" |

### 5.3 结论由代码重算，不由 agent 自己放行

- 评估记录里写测试数据，**结论由核心库按规则重算**；档案检查发现记录里写的结论和重算的不一致 → 错误。
- **复盘数据**：周复盘同时写结构化的 `复盘/<段>-<周>.json`，数字照使用者说的填：
  - 训练次数、打卡达标天数、散步和放松天数、不适；
  - 逐个动作的表现（每组是否做满上限、最后一组剩几次余力）和进度改动；
  - 65 岁以上：本段有没有摔倒、头晕差点摔倒（出现就先看医生，`senior/next.md` 原文）；
  - 6–12 岁：生病天数（成功线按设计值 `SICK_A06` 折算）。
- **训练次数以复盘数字为准**，练习记录只作下限核对（复盘写的次数不能少于这一周导出的练习记录数）。健身房、65 岁以上的平衡动作、6–12 岁本来就没有或只有部分练习记录，不能只看练习记录。
- 使用者口述的数字由使用者负责；代码核对的是"按这些数字，结论对不对"。

### 5.4 人群和条件

| 人群或条件 | 怎么判定 | 结论 | 附加内容 |
|---|---|---|---|
| 超重（18–64 岁 BMI 24–27.9，`BMI_CN`） | 入门评估 | 可以开始 | 《超重与肥胖》附册：低冲击替换；稳定期可选减脂 |
| 肥胖（18–64 岁 BMI ≥ 28） | 筛查已有这一项 | 医生同意后开始 | 同上；饮食照《成人肥胖食养指南》 |
| 65 岁以上的体重 | — | 不谈减重（红线不变） | 照高龄老年人体重管理标准的原意提醒"问医生"，不给目标 |
| 慢性病 | 筛查"是" | 医生同意后开始，**用的仍是现在的完整计划**（不改成"低强度版"，见第十一节） | 运动：照医生的调整，模板不按病分处方；饮食：《慢性病饮食参考》附册，照对应食养指南原文 |
| 训练单的适用条件（有高血压、骨质疏松、家里没有别人、没有跳跃场地、有没有家长在旁边） | 档案记录（第十一节第 1 条已定：记） | 导出对应版本；**条件没确认时用规则层为这个条件写明的保守版本** | 规则层逐个条件写：条件名、正文出处、没确认时的默认版本；默认版本里的动作必须在动作索引里（如 13–17 岁"没地方跳换高抬膝踏步"、第 1 周"只练落地定住"，阶段 1 先补进动作索引；补不进的标"照成品做"） |
| 禁用组合 | 规则参数 + 核心库判断 | 代码拦下 | 65 岁以上不选减脂、增肌；6–17 岁不选目标；筛查第 3 项"是"不出任何个人化饮食（4.5） |
| 不覆盖 | 筛查 | 不出计划 | 不变（学龄前、孕期和产后 6 个月内） |

- 儿童青少年超重肥胖：不谈体重的红线不变；只用《儿童青少年肥胖食养指南》里对家长的饮食和活动建议，写进全家餐饮和 6–12 岁、13–17 岁成品，不给孩子定体重目标。
- "确诊慢性病"在入口问卷里的说法是"先问医生，按医生的建议选择活动和饮食"，不是"不覆盖"，和上表一致。

### 5.5 年龄跨段和中断

| 情况 | 规则 |
|---|---|
| 未成年人 | 按学段，不按年龄：档案记学段和入学年份，按 9 月 1 日推算升学；**高中在读满 18 岁仍用 13–17 岁版，毕业后换成人版** |
| 成年人 | 档案记出生年月；满 40 岁换 40–64 岁版；满 65 岁触发评估（是否必须换椅子版待你决定） |
| 推算的年龄段和档案成品对不上 | 档案检查报错，提醒做触发评估 |
| 换成品（跨段、换场地，`next.md` 本身就建议可以换版本） | 新开一段，段的计数按新成品重新从第 1 段算；个人进度截到新成品本周允许的最高级（如 18–39 岁练到的保加利亚分腿蹲，换到 40–64 岁版要退回到这一轮允许的级），次数截进新成品这个动作的区间，重量不变；第 1–2 周照新成品的正文重新找级 |
| 中断 | 断多久算中断登记为设计值，代码按练习记录的日期提醒。处理**照各成品原文**：成人"不补、不清零、不从头再来，回来第一次只做一半的量"（"一半"的含义登记设计值，如每个动作组数减半、向上取整，次数不变；半量的课也要能导出）；65 岁以上"生病、住院回来，先问医生，能练从第 1 周重新开始"；没有原文的，登记设计值 |

## 六、主仓库

### 6.1 数据格式

| 格式 | 改动 |
|---|---|
| 个人档案 `yangxia.profile/1` | `round`、`weeks` 合并成一个**段序列** `segments`：每段 `{product, phase, type, n, week, goal, start}`（成品、阶段、段型、第几段或第几个周期、周、目标、开始日期）；周的上限按阶段（起始 4、稳定 12），每次最多推进一周不变。新增 `birth` 或 `school`、`progress`（每个动作的级、次数、重量、轮换位置、器材选择、医生同意的超上限项）、`conditions`（训练单用到的几项条件，每项"是 / 否"，没记的按"没确认"）、`level`。档案的 `product` 等于最后一段的成品 |
| 评估记录 `yangxia.assessment/1`（新） | `profiles/<代号>/评估/<日期>.json`：种类、测试数据、身高体重腰围（只限 18–64 岁）、结论、依据的规则 ID |
| 复盘数据 `yangxia.review/1`（新） | `复盘/<段>-<周>.json`：5.3 说的数字、逐个动作的表现和进度改动；和同名 `.md` 成对 |
| 课程 `yangxia.course/1` | `source` 加 `phase`、`segment`、`goal`；新增字段，不升版本 |
| 练习记录 `yangxia.session/1` | 每个动作加可选的 `feel`（找级的三种感受，照正文原话；健身房动作记"还能做几下"）、`reverted`（升级做不到当场退回）；新增字段，不升版本。编排器的练习记录表单加这两项（阶段 1 做） |

项目没有真实历史数据（只有虚构的演示档案），刚加的 `round`、`weeks` 直接换成 `segments`，样例和演示档案一起改。`历史/` 按段归档：`历史/<段>/`。

### 6.2 课程：由命令生成

- 新命令 `npm run course -- export <档案> <第几周> <哪天>`：训练单 + 档案进度 + 适用条件 + 取舍 → 课程；`quote` 填训练单和阶梯表的出处。
- `course check` 新增"和训练单 + 档案进度逐项核对"。原文核对只用于起点课程（4.2 第 4 条）：阶段 1 里两种核对并行跑在起点课程上，结论一致后，带进度的课程只走新核对。
- 手改过的课程（`edited`）对不上，检查报出来，周复盘不按它加量（现有规则）。

### 6.3 档案检查新增

- 段序列结构；阶段转换、进度改动都要有对应的评估或复盘数据支撑，结论由代码重算。
- 年龄段推算和成品不一致 → 错误；距上次筛查超过一年 → 提醒；中断 → 按 5.5 提醒。
- 禁用组合 → 错误；评估记录里出现 6–17 岁的体重、腰围、BMI → 错误；测试项不适用于这个年龄段 → 错误。

## 七、安全和边界

- **不变的底线**：只在模板规则之内定制；筛查不能跳；6–17 岁不谈体重热量；65 岁以上不跳跃、不闭眼、不憋气、不减重；疼痛头晕胸闷不加量；不是医学建议。
- **新内容强度更高**（稳定期、增肌、有基础的人从更高的级起步），附册涉及慢性病饮食：全部标"未经专业审核"；建议发布前请运动、营养、康复专业人员审，附册尤其需要（第十一节）。
- **不做疾病处方**：慢性病只照医生的调整和食养指南原文；65 岁以上不用肌少症指南的参数；条件变体只照正文已有的写法，不新编。
- **官方数字**：先核对原文，核实 ✅ 或 ☑️ 才能用；查不到的登记设计值，正文标"（模板建议）"。

## 八、隐私

- 新增的个人数据：出生年月或学段、成年人的身高体重腰围、测试结果、进度、适用条件（第十一节第 1 条已定：记，只记"是 / 否"，不记诊断细节和用药）、（待定）饮食模式。都只放 `profiles/<代号>/`，不提交。
- **饮食模式标签实际上能看出病**（低嘌呤约等于痛风，优质低蛋白约等于肾病），记不记、怎么跟使用者说清楚，见第十一节。
- 6–17 岁不记体重、腰围、BMI。
- 读档案时内容会发给模型服务处理，建档时如实告诉使用者（现有规则，onboard 补上新数据的说明）。

## 九、分阶段实施

每个阶段单独提交；模板仓库在 `v4-structure` 分支上做，合并回 `main`、发版由用户决定。每个阶段的验收都包含"同步清单"：两个仓库的 AGENTS.md（"只读 dist/"加上 `dist/data/`、"现在在做什么"指向 v4）、数据约定、skills、提交前检查（两仓库同一份，新格式 `yangxia.assessment`、`yangxia.review` 加进个人数据规则）、每轮结束的检查（认得 `评估/` 和新文件）、离线样例。

| 阶段 | 做什么 | 验收 |
|---|---|---|

## 十、风险

| 风险 | 应对 |
|---|---|
| 正文和训练单说法不一致 | 模板 `check.py` 从正文独立推出每天清单比对，提交前检查会跑；主仓库原文核对作第二层 |

| 新内容没有专业审核 | 标"未经专业审核"；建议发布前请专业人员审 |
| 评估测试本身有风险 | 只用次最大测试；按年龄段登记、过红线；65 岁以上医生同意、有人在旁 |

| 内容量大 | 按阶段验收，一次推进一个年龄段或一个目标 |
