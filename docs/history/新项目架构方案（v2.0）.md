# 「规律生活」新项目架构方案（v2.0 草案）

> 目标：把现在的 `living`（v1.9）整理成一个结构清晰、可以长期维护、方便接入别的系统的**独立新项目**。
> 原则：**内容一个字不改，保留 v1.9 最新版**；构建机制保留，但重新设计目录、模块和数据格式。
> 验收：新项目构建出的 10 份成品、87 张图与 v1.9 **逐字节相同**（菜谱手册例外，见第五节）。旧的 `living` 文件夹原样保留。

---

## 一、现状梳理（v1.9）

| 部分 | 现在在哪 | 规模 | 问题 |
|---|---|---|---|
| 成品清单 | `src/products.md` | 10 份 | 还好 |
| 章节顺序 | `src/layouts/<年龄段>.txt` | 6 个 | 还好 |
| 章节正文 | `src/sections/<章节>/<变体>.md` | 30 个章节、92 个文件 | 所有年龄段混在同一个文件夹里，改 65+ 的内容要在 30 个文件夹里找 `a65.md` |
| 片段 | `src/snippets/<名字>/<变体>.md` | **102 个目录、342 个文件** | 最大的问题：一半是 `checkin-01 … checkin-17`、`energy-01 … 13` 这种**按编号命名**的碎片（当初用脚本从三份原稿逐段拆出来的），看名字不知道内容；而且**每个片段只在一个地方用**，没有复用价值，只是为了表达"健身房 / 居家 / 徒手这一段不一样" |
| 参数 | `params/参数表.md` | 官方 211 + 设计值，混在一个文件 | 官方参数（构建要用）和设计值（只作登记）放在一起 |
| 示意图 | `build/figs/*.py` 9 个文件 + `build/figures*.py` | 约 1 万行代码、87 张 | 和构建脚本混在 `build/`；`figmap.tsv` + `place_figures.py` 是一次性插图工具，现在图链接已经写在正文里，它们只剩历史意义 |
| 菜谱手册 | `recipes/三餐菜谱手册.md` | 1 份 | **不经过构建**，里面的官方数字和依据表要手动跟参数表同步 |
| 构建 / 校验 | `build/*.py` | 8 个脚本 | 没有统一入口；`split.py` 是用过一次的拆分工具 |
| 文档 | 根目录 README、CHANGELOG、设计方案、调研报告 | 设计方案约 800 行 | 设计方案里"现行架构"和 v0.2–v1.9 的历史附录混在一起，第五章的目录结构已经过时 |
| 原稿 | `archive/` | 3 份 | 只有 check.py 拿来算"改了多少行"，意义不大 |
| 历史压缩包 | 根目录 `v1.0 … v1.9.zip` | 10 个 | 和项目文件混放 |

关键事实（用脚本统计过）：
- **没有任何章节文件同时被成人版和其他年龄段使用**——6–12、13–17、65+、全家这四份各自独立，成人 6 份（18–39 / 40–64 × 健身房 / 居家 / 徒手）共用一套。
- **102 个片段全部只被一个章节引用**，没有一个是真正复用的。
- 同一章节或片段的不同场地版本之间有大量重复内容（252 对变体里有 38 对相似度 > 90%）。

## 三、核心改动

### 1. 按"给谁用"分文件夹

`content/adult|teen|child|senior|family/`，每个文件夹自带章节顺序 `_layout.txt`。改 65+ 的内容，只看 `content/senior/`。

### 2. 用"版本块"取代 102 个编号片段

现在成人章节里写的是 `{{> checkin-05}}`，再去 `snippets/checkin-05/` 下找 gym / home / bw 三个文件。新写法把各版本直接写在原位：

```markdown
| 训练 |
<!-- 版本 健身房 -->
**3 组**，正常速度，第 1 周的重量不变 |
<!-- 版本 居家、徒手 -->
**3 组**，正常速度，难度级不变 |
<!-- 版本 40-64·徒手 -->
…
<!-- 版本结束 -->
```

- 用 HTML 注释写，Typora / VS Code 预览时不会乱。
- 条件可以写场地（健身房 / 居家 / 徒手）、年龄段（18-39 / 40-64），或两者组合（`40-64·徒手`）；内容相同的版本合并成一个分支。
- 迁移脚本自动转换：对每个片段，算出 6 份成人成品各自实际用的是哪个变体，内容相同的合成一支——**按构造保证成品不变**，再用 `verify.py` 逐字节确认。
- 结果：`snippets/` 整个目录消失，成人每个章节的全部内容在一个文件里看全。

整章都不同的（比如健身房版和居家版的动作库），仍然按 `章节.场地.md` 拆文件，覆盖顺序沿用现在的规则（`年龄段.场地` > `年龄段` > `场地` > 通用）。

### 3. 参数表拆成两份

`官方参数.md`（构建引用、核实标记、复核触发）和 `设计值.md`（只登记）。表结构、ID、取值不变。

### 4. 菜谱手册纳入构建

把手册里硬写的官方数字换成 `{{参数}}`，末尾的"依据版本"表由构建自动生成——以后改参数表，手册自动跟着变，不用再手动同步。

### 5. 示意图独立成 `figures/`

- 9 个分组文件按内容重新命名（如 `gym.py` / `gym2.py` → `gym_ab.py` / `gym_cd.py`），代码不改。
- 图的位置以正文里的 `![…](img/图号.svg)` 为准；`figmap.tsv` 和 `place_figures.py` 退役（插图已经完成），改由 `check.py` 检查"每张定义了的图都有成品引用、每个引用都有图"。

### 6. 一个命令入口

```
python3 guilv.py all       # 生成图 → 构建 → 校验（日常用这一条）
python3 guilv.py build     # 只构建
python3 guilv.py check     # 只校验
python3 guilv.py manual    # 生成 PDF 手册（需要 playwright）
python3 guilv.py verify    # 和 v1.9 逐字节比对（迁移验收用，验收后保留作回归测试）
```

### 7. 退役

`split.py`（一次性拆分工具）、`place_figures.py` 和 `figmap.tsv`（一次性插图工具）、`check.py` 里和 `archive/` 比行数的信息项。

## 四、迁移步骤

1. 把 v1.9 复制成新项目，按第二节的目录搬文件、改名（脚本完成，不手工改内容）。
2. 运行转换脚本：编号片段 → 版本块；参数表拆分；菜谱手册换成 `{{参数}}`。
3. 改构建工具：新目录结构、版本块语法、统一入口、manifest。
4. **验收**：`verify.py` 比对 10 份成品和 87 张 SVG 与 v1.9 逐字节一致；`check.py` 0 错误 0 警告；Python 3.9 / 3.10 结果一致；PDF 手册页数、目录一致。
5. 重写 README（用户部分）、维护指南、架构说明；设计方案原样归档。
6. 版本号定为 **v2.0**（内容同 v1.9，只是结构变了），CHANGELOG 写明。
7. 打包交付到你指定的新文件夹，旧 `living` 不动。

## 五、内容会不会变

- **10 份成品、87 张动图、PDF 手册**：与 v1.9 完全相同（唯一变化是封面版本号 v1.9 → v2.0）。
