# 养夏自托管版需求文档

> 状态：**v3 定稿**（2026-11-24，经首轮审查与独立复审后修订收口，第六节 8 项首版决策已全部确认；后续按实施与实机效果视情况微调，修订记录见第七节）。
> 基线：主仓库 `v1.0.0` + 模板仓库 `v1.0.0`（养夏最后一个本地优先、离线版本，含阶段 8c 课程包与练习记录导入，模板已含阶段 9 新手培训期内容）。
> 范围：本文档定义自托管版的**产品目标、核心需求、三端职责、非功能与安全约束及首版已定决策**；具体技术设计与分阶段实施计划另写架构方案。
>
> **声明**：养夏所有计划与跟练提示均**未经专业审核，不是医学建议，不能替代医生的判断**。

## 一、背景与要解决的问题

`v1.0.0` 本地离线版已完成“建档 → 评估 → 导出课程包 → 手机跟练 → 导入练习记录 → 周复盘 → 排菜单”的功能闭环；但在 `8b-0` 真机验证、实现收口及架构推演中，暴露出四类结构性瓶颈：

1. **手机浏览器权限差异与 Web 能力边界**：
   - 本地打开 `.html` 在不同平台和浏览器间表现割裂（按 `8b-0` 真机实测）：Mac Edge 打开本地文件时屏幕常亮、复制、全屏均正常；但安卓（小米 Android 16）从文件管理器打开时，Edge 拒绝了屏幕常亮、复制和系统文件分享（全屏与默认系统语音可用），而夸克常亮、复制、分享正常却缺失系统语音（`speechSynthesis`）；iPhone 未实测，从“文件”或聊天软件点开 `.html` 存在仅进预览不执行脚本的已知风险。
   - 此外，现有网页版为了规避浏览器后台限制有意设计成“切后台自动暂停”；若想进一步支持**息屏/后台持续纯语音跟练、与外部音乐 App 协同音频焦点**等原生体验，纯浏览器环境难以稳定实现。
2. **文件往返割裂、家庭场景门槛高**：电脑导出课程包 `.html` → 发到手机 → 练完保存/分享练习记录 `.json` → 传回电脑导入档案，流程繁琐；家里老人（65 岁以上）或孩子很难自行处理文件传输与导入。
3. **缺少账户与多设备同步**：本机偏好、方案库和训练进度绑定在单一设备/浏览器中，无法跨电脑、手机、平板同步，也不便于统一管理家庭多成员档案。
4. **本地命令行 Agent 的使用门槛**：当前依赖本机终端里的 Claude Code 驱动，非技术成员无法直接在网页或手机端完成日常交互与排课。

## 二、产品定位与核心目标

从本地优先工具演进为**面向个人与家庭的私有自托管服务**（数据保留在用户自己的电脑、NAS 或私人服务器中，不面向公众开放注册）：

- **服务器端**：作为唯一规则引擎、数据中枢与 Agent 运行环境，负责账户/多档案管理、安全校验、课程生成、练习记录回收与同步。
- **网页端**：作为排课与管理工作台，负责建档、评估、排课、周复盘、计划单/正文与菜单管理、以及与服务端 Agent 对话。
- **原生移动端**：直接走**Android 原生 App 路线**，作为专注跟练的瘦客户端——登录拉取服务端生成的课程交付信封，提供不受手机浏览器差异影响的原生跟练体验，练完一键回传练习记录。

## 三、核心功能需求

### 3.1 账户、家庭多档案、权限、迁移与时区

| 编号 | 需求 | 说明 |
|---|---|---|
| A1 | 自托管账户与密码重置 | 支持管理员初始化与多账户登录，所有接口严格按登录身份鉴权。面向无外发邮件服务的自托管场景，明确密码重置途径：管理员通过服务端 CLI 重置，普通成员由管理员在后台重置 |
| A2 | 家庭多档案与年龄段边界 | 支持单个家庭内管理多名成员档案（覆盖 6–12 岁家长版、13–17 岁、18–64 岁、65 岁以上），支持“管理员代管子档案”和“独立账号成员”并存。**年龄段边界**：`6-12 岁-户外与游戏版（家长版）` 照成品原文做、不导出课程，仅在服务端/网页端管理建档、计划单、成品正文阅读与周复盘，**无手机端跟练课程**；手机直达跟练仅适用于可导出课程的版本（13–17 岁、18–64 岁、65 岁以上） |
| A3 | 角色权限矩阵与隐私隔离 | 延续“用代号不用真名、筛查只记是/否、6–17 岁不记身高体重腰围、不记病名与用药细节”的隐私红线，并按四类角色/设备明确权限：<br>① **管理员**：管理被代管子档案（老人/孩子）及系统设置，但**不越权查看其他独立成年人账号的私密数据**；<br>② **独立成年人账号**：彼此严格隔离体重、腰围、减脂/增肌目标、进食困扰记录与 Agent 对话历史；排全家菜单时仅共享 `household` 年龄段，**不在菜单中暴露其他成年人的目标或筛查结果**；<br>③ **13–17 岁可登录成员**：仅可查看/跟练本人课程与提交练习感受，不可自行修改年龄段或篡改安全筛查；<br>④ **扫码绑定跟练设备**：绑定二维码须**一次性且短时效（如 5 分钟）**，设备凭证限定为**单档案跟练瘦权限**（仅允许拉取该档案课程与动图、回传练习记录、调整允许范围内的播放偏好，不可改档案/调 Agent/访问他人档案），纳入 4.2 设备列表与一键吊销 |
| A4 | 本地 `v1.0.0` 数据完整迁移 | 支持导入 `v1.0.0` 的 `profiles/<代号>/` 目录，按四类文件处理：<br>① **必迁结构化数据**：`档案.json`、`课程/*.json`、`打卡/*.json`、`复盘/*.json`、`评估/*.json`（**含 `历史/第N段/` 归档目录下全部同类文件**，这些历史文件仍参与不适追踪、训练间隔与段末统计）；完整保留或无损映射 `progressLog[].evidence` 所引用的三类路径（`打卡/…`、`复盘/….json`、`评估/….json`）与 `segments[].restart`，自动补齐档案 `timezone`，迁入后跑通全档案核对 0 错误；<br>② **只读历史文档归档**：`计划/*.md`、`菜单/*.md`、`复盘/*.md`（含 `复盘/月度总结.md`）迁入后作为只读历史记录展示，且**历史 `计划/*.md` 免于按新模板重跑 `checkSheet` 报错**；<br>③ **跳过不迁**：`课程/*.html`（含 `历史/` 内单文件课程包）及其他非契约文件（如 `.ics` 日历、`.DS_Store` 等隐藏文件），导入完成后向用户明确列出已跳过项；<br>④ **明确不可自动迁入项**：旧浏览器 `localStorage` 中的本机偏好与方案库不在 `profiles/` 内，导入时提醒用户在新端重新设置 |
| A5 | 用户时区规范 | 每个档案记录所属时区 `timezone`（存为档案元信息，默认 `Asia/Shanghai` 并支持配置）；“今天”、周次起止、复盘窗口与练习记录日期核对均按**档案所属时区**计算，不依赖服务器系统时区（如 Docker 默认 UTC）或出差设备临时时区 |

### 3.2 服务器端：课程生成、规则校验与数据中枢

| 编号 | 需求 | 说明 |
|---|---|---|
| S1 | 复用核心规则库（含三项前置重构） | 服务端复用 `@yangxia/course-core`，**只读完整 `templates/dist/` 发布目录**（含 `manifest.json`、`data/*.json`、20 份成品与附册 `.md`、`三餐菜谱手册.md`、`img/` 图解及手册，保证 `checkCourse` 正文核对与菜单/附册阅读完整可用）。转向自托管服务端必须先完成三项前置重构：<br>① **解耦 `cli.ts` 文件系统依赖**：将 `packages/course-core/src/cli.ts`（929 行、24 个函数）中的目录扫描、档案综合检查、课程/进度/记录核对、评估上下文拼装、记录导入去重等编排逻辑下沉为与存储无关的库函数/Service 层，供 CLI 与服务端共用；<br>② **全库日期与时区计算参数化**：消除 `progress.ts`、`assess.ts`、`fallrisk.ts`、`goals.ts`、`sheet.ts`、`cli.ts` 中对进程本地时区的硬编码依赖，统一通过显式档案 `timeZone` / `Clock` 注入；<br>③ **规范包导出与纯 JS 产物**：补齐 `packages/course-core/src/index.ts` 的服务端规则模块导出，并拆分移动端零 Node 依赖子入口及编译打包产物 |
| S2 | 确定性课程生成与交付信封 | 统一由服务端按档案进度、阶段（起始期/稳定期）、目标（保持/减脂/增肌）、条件与安全下限生成课程（`yangxia.course/1`）和个人计划单；生成前强制通过安全筛查与复盘放行校验。**向移动端下发课程交付信封**：除标准 `yangxia.course/1` 外，一并携带服务端同步算出的只读 `ExportResult.follow`（当天“照成品做”清单）、`notes`（含 `per_session` 每次练前确认——第一轮修复起单独放在结构化的 `checks` 里，65 岁以上另有每次练前的摔倒一问——、65+ 摔倒后禁练平衡动作提醒、本周有氧稳态/间歇与减脂分钟数、时间不够先砍顺序、半量与热身提示）、课程快照版本、动图片段哈希与免责声明 |
| S3 | 进度、评估与复盘核对 | 建档筛查、四种现有评估（`入门` / `段末` / `周期末` / `触发`；下一迭代接入阶段 9 后包含模板 `v1.0.0` 已定型的第五种 `kind: "培训"` 掌握评估，见决定 6）结论重算、每周复盘放行、不适停加量、个人进度日志重放全部在服务端以确定性代码校验，0 错误才生效 |
| S4 | 练习记录回收、并发与冲突安全 | 接收移动端回传的练习记录（`yangxia.session/1`）并校验归属、格式与去重入库，须满足 5 条安全约束：<br>① **单档案串行事务 / 乐观锁**：防止网页表单、Agent 工具与手机补传并发写同一档案造成非法状态组合；<br>② **多档案安全去重**：因 `courseIdFor` 不含档案 ID，去重键须绑定 `(profileId, courseId, startedAt)` 或客户端幂等键；<br>③ **不可抹除不变量**：延续 `cli.ts` 硬规则，已记下的 `pain` / `dizzy` / `chest` 症状及 `edited: true` 不可通过重传、覆盖或删除抹为没有；<br>④ **复盘后迟到记录处理**：若上周离线记录（尤其含不适）在周复盘推周后才补传，**绝不丢弃**，必须照常入库、重跑全档案核对、拦截后续课程导出并向网页端与移动端发出“复盘与不适冲突待修正”强告警；<br>⑤ **旧机时钟漂移容错**：若无卡旧机（如 Mi 6）时钟偏快超过允许阈值（如未来 5 分钟），返回明确时间校准提示并保留本地队列，不静默丢弃 |
| S5 | 动图与资源增量下发 | 服务端读取模板 `motions.json`（3.18 MB、67 个片段），向移动端按**单课引用的片段 ID + 片段级内容哈希**增量下发与缓存（单课仅约 4–6 个片段、300–500 KB），避免重复拉取整包 |
| S6 | 模板更新与版本联动 | 基于**模板发布物契约 `format` 字段校验（`yangxia.manifest/1` 等）+ 发布物内容哈希/版本快照**管理兼容性（不假设模板版本号单调递增）。模板升级后：① 历史课程与记录按生成时快照保留不受破坏；② 对当周已发布课程自动重跑 `checkPlanCourse`——0 错误（允许提醒）时手机端已缓存课可继续练完，出现处方或安全下限 error 则强制标记作废并提示重新生成；③ 课程信封记录配套动图片段版本/哈希以防错帧 |

### 3.3 服务器端：Agent 核心

| 编号 | 需求 | 说明 |
|---|---|---|
| G1 | 业务职责 | 承接现有 `.claude/skills/` 中的用户交互流程：建档引导、安全筛查问答、评估引导、排课沟通、周复盘整理、全家菜单编排与日常答疑 |
| G2 | 工具调用受控（只读 + 八大校验型写入工具域） | Agent **不拥有宿主机 Shell 或任意文件读写能力**；只能调用围绕 `@yangxia/course-core` 封装的强类型业务工具，且 `userId / profileId` 由服务端鉴权层注入以防止越权。<br>- **只读工具**：查询档案状态/评估项目/练习记录、按需检索 `templates/dist/*.md` 成品正文（含全家餐饮模板、菜谱手册、“疼了怎么办”、打卡表与食养指南附录）。<br>- **八大校验型写入事务工具域**：① 建档初始化；② 档案受控字段更新（含 `screening`、`choices`、`household`、`playback`、`dietByPro`、`conditions`、`body`/`bodyLog`/`bodyStopDate`、`segments`、`progress` 与 `progressLog` 同步重放、医生同意与加项记录、跨段/升学/换场地/改起床时间）；③ 评估提交（含命令重算结论）；④ 周复盘（`.md`/`.json`）与 `月度总结.md` 写入；⑤ 个人计划单生成（`course plan`，不手写）；⑥ 跟练课程生成发布（`course export`，含过重旧课作废）；⑦ 菜单写入（`.md`）；⑧ 段归档（旧段归档）。每次写入在同一数据库事务内完成规则校验、免责声明校验与红线检查，0 错误才提交 |
| G3 | 安全硬护栏 | 安全拦截、下限强制、评估重算和红线检查均在工具内部由代码执行，不依赖模型自觉；所有输出遵循免责声明与年龄红线 |
| G4 | 模型可插拔与最低能力要求 | 自托管用户可在后台自由配置大模型提供商与 API Key（支持 Claude、Gemini、OpenAI、DeepSeek、OpenAI 兼容接口或本地模型），不被单一模型厂商绑定。**能力约束**：工具层代码能守住安全底线，但现有 skills 的多轮建档、复盘与工具调用质量仍高度依赖模型能力；需在文档和配置界面写明**最低推荐模型规格**（稳定的中文多轮对话、严格指令遵循与可靠 Tool Calling），提示小模型/本地模型可能出现漏问、反复调用失败等体验降级 |
| G5 | 底座演进路线（已定） | **首版采用 Vercel AI SDK (`ai`)**，待 **`dsh`（DeepSeek Harness）发布稳定版本后再迁移**；MCP Server 首版暂不强绑，预留同源业务 Tool 接口后续按需挂载。为保证未来低成本平滑切换，架构须满足三条解耦约束：① 业务 Tool 定义与 `@yangxia/course-core` 调用完全独立于 SDK 私有类型；② 对话会话与业务数据存储在自有数据库（如 SQLite），不绑定框架私有会话格式；③ Prompt / Skill 模块独立维护，仅通过一层薄 Agent 适配器接入运行时 |

### 3.4 网页端：排课与管理台

| 编号 | 需求 | 说明 |
|---|---|---|
| W1 | 排课中心 | 查看当前周个人计划单、按规则处理**半量课（`--half`）与轮换组选择（`--pick`）**、一键生成并**发布到服务端，由对应成员手机端打开或下拉刷新时自动拉取同步（Pull）**（不编处方、不默认依赖 Google FCM 或厂商 Push 通道） |
| W2 | 档案、进度与正文阅读 | 展示和切换有权限访问的家庭成员档案，查看当前阶段/周次、习惯达标线、个人进度日志、安全筛查状态、医生同意记录与下次评估提醒；提供只读的**成品正文、热身拉伸、“疼了怎么办”、《超重与肥胖》附册、《官方食养指南》附录与图解查看**（保障 `6–12 岁家长版` 及所有用户无本地模板文件时也能完整阅读） |

## 四、非功能与安全约束

### 4.1 养夏安全底线、模板边界与跨端一致性
1. **安全底线零妥协**：`v1.0.0` 已建立的全部安全规则（安全筛查、65 岁以上医生同意与跌倒风险自查、周复盘放行、不适停加量、不编处方、区间取轻松端、红线检查、未经专业审核声明）在自托管版中**全部保留且继续由代码强制核对**。
2. **模板仓库独立性不变**：主仓库与自托管服务端只消费 `YangXia-templates` 的发布产物，不耦合其内部源码。
3. **跨端一致性验收**：所有业务判定归服务端唯一裁决；移动端涉及的时间轴计算、完成组数统计（`session.ts`）、跟练状态展示（`live/view.ts`）与动图帧插值，须以**建设并运行跨端黄金测试集（Golden Fixtures，统一 `voiceDuration` 为 `estimateVoiceSeconds`）**作为独立交付与回归验收项。

### 4.2 部署、网络与数据安全（健康数据托管必选项）
健康筛查、体测、不适反馈与未成年人记录集中存放在服务端后，以下安全能力为必须项：
1. **分阶段网络接入与客户端明文限制**：**首版先完成内网（局域网）直连**打通闭环；服务端与移动端从首版即支持**可配置的服务器地址（Base URL）**，便于后续零重构平滑接入**反向代理 HTTPS** 或 **私有组网（Tailscale / WireGuard）**。
   - **Android 明文校验**：不依赖不支持 CIDR 网段通配的 `network_security_config.xml`，而是在**应用网络层（HTTP 拦截器 + 重定向目标校验）**强校验 `http://` 仅允许目标解析至 RFC1918 私网或回环地址（后续接 Tailscale `100.64.0.0/10` 时按配置显式放行或统一走 HTTPS），公网地址一律拒绝明文 HTTP（同时覆盖 API 26–27 与 28+）。
   - **受信任反代**：服务端仅在显式配置受信任反代来源时采信 `X-Forwarded-*` 头，并据此切换会话 Cookie 的 `Secure` 属性。
2. **认证、会话与设备管理**：密码采用强慢哈希加盐存储；登录会话/Token 与扫码绑定设备凭证均支持过期、续期、设备列表查看与一键主动吊销（支持踢出丢失的手机）。
3. **数据备份、恢复与密钥保管**：提供数据库与文档资产的定期自动备份、手动导出与一键恢复能力，支持备份加密且**备份密钥与备份文件分离保管**；用户配置的大模型 API Key 须加密存库，前端永不明文回显。
4. **脱敏审计留痕**：对档案创建/修改、安全筛查变更、医生同意日期更新、个人进度调整、复盘放行等关键写入记录审计日志；**仅记字段级非敏感元数据**（操作人、时间、档案 ID、操作类型、字段名/规则名），**严禁写入体重、腰围、进食困扰、医生意见或备注原文 diff**，防止删改或停记后敏感值仍滞留日志。
5. **外部模型传输与对话历史隐私**：向用户配置的外部大模型 API 发送对话和档案摘要前，在界面和配置页如实告知数据流向；除此之外不向任何第三方发送数据。Agent 对话历史支持用户手动清除与配置保留期，高敏录入优先引导走不进外部 LLM 与聊天历史的网页表单（见 W5）。

### 4.3 部署与工程规范
- 保持单机自托管友好（如 Docker Compose + SQLite，零重型外部中间件），便于个人与家庭长期维护。
- 延续本仓库提交前检查与依赖版本锁定规范，核心逻辑与接口变更均配套自动化测试。

## 五、不做的事项（明确边界）

- 不面向公众做公开注册的多租户 SaaS 运营（避免医疗免责与大规模敏感健康数据公网合规风险）。
- 不做 App 内定时提醒，也不默认对接 Google FCM 或国内各手机厂商推送通道（以手机主动拉取同步为主；定时提醒由外部项目负责并通过 M8 拉起联动）。
- 不在移动端重复开发排课后台、高级动作编辑器、视频离线导出和离线神经 TTS（重管理与导出留在网页/桌面端，长句讲解在无中文 TTS 时降级为纯大字）。
- 不再继续在“单文件离线 HTML 课程包”上叠加同步或账号功能（纯本地版以 `v1.0.0` 为最终里程碑）。
- 不编造官方模板之外的训练处方、医学建议或慢性病个人化饮食数字。
