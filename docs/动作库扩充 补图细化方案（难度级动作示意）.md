## 一、要做什么

有些难度级换了支撑、负重或单腿，现有的图和这一级的做法对不上，阶段 7 就没给它们显示动图。这一批**只画图、登记、插进正文**：

- **跟练**：这些级显示对得上的动图。
- **成品**：新图插在这一级的说明旁边。第 2.3 节复用现有图的几级，成品里不另外插图（第九节第 1 问）。

| 做 | 不做 |
|---|---|
| 给清单里的级画新图，登记到 `content/rules/动作示意.md` | 改任何处方、阶梯、动作 ID |
| 新图插进成品正文，图解手册跟着更新 | 新增动作、新增难度级 |
| `motions.py` 支持新的分级图；课程检查对"少了动图"放宽为提醒 | 新增数据格式；动编排器 |
| 两个仓库同步更新离线样例、重新打包编排器 | 拿相近的图顶替 |

## 三、怎么做

### 3.1 图的样式：分级小图

照 `pushup-ladder`（俯卧撑难度阶梯）的样式：每一级一个面板，左边侧面动图（带成对的呼吸标签），右边第二视角，下面 2–3 条要点。

- **只省文字，不省画面**：做法、常见错误仍以原来那张完整图和正文为准，但每个面板的场景要画全（椅子、墙、桌子、垫子、枕头、哑铃、背包），因为跟练只播这一格。
- 图下写"其余做法见《原图标题》"，不写"上一张图"（手册的排序不一定挨着）。
- 呼吸节奏：一个面板只对应一个家族、一种原文时照抄原文；对应几级或几种原文时（例如臂屈伸第 2、3 级），写"呼吸节奏照正文"。
- 图里不写组数、次数、重量（`README.md` 的规定），不写"2.5kg"。
- 同一家族、同一动作要补的几级放在一张图里；13–17 岁和成人的面板不放在同一张图里。

暂定的图（都画是 11 张、17 个面板；第 2.3 节三处直接用现有的图时是 10 张、14 个面板）：

| 图号 | 面板 | 用在 |
|---|---|---|
| `squat-load` | 胸前抱背包 | 成人居家、纯徒手 |
| `a13-squat-chair` | 坐椅深蹲 | 13–17 岁 |
| `glute-bridge-db` | 胯骨上横放哑铃 | 成人居家 |
| `sl-rdl-bw-levels` | 扶墙；双手抱背包 | 成人纯徒手（扶墙那一格也给骨质疏松用） |
| `sl-rdl-home-levels` | 扶墙、空手；扶墙、拿哑铃；拿哑铃不扶 | 成人居家（扶墙、空手那一格也给骨质疏松用） |
| `chair-dip-straight` | 双腿伸直 | 成人居家、纯徒手 |
| `table-row-levels` | 膝盖弯曲、脚踩地；脚搭椅子 | 成人居家、纯徒手 |
| `pike-pushup-levels` | 高位派克（如不复用）；脚抬高派克 | 成人纯徒手 |
| `a13-split-squat-wall` | 扶墙 | 13–17 岁 |
| `a13-sl-rdl-wall-levels` | 一根手指点墙；不扶（如不复用） | 13–17 岁 |
| `a13-pike-ground` | 地面派克（如不复用） | 13–17 岁 |

- **深蹲抱背包**：画背包抱在胸前，居家（"哑铃或背包……在胸前"）、纯徒手（"背包"）都对。纯徒手原文没写背包抱在哪（`moves.bw.md:143`），单腿硬拉"双手抱背包"也没写位置（`:231`）。照 `docs/正文歧义清单.md` 的格式登记，"现在怎么处理"写：深蹲双手抱在胸前（照居家原文）；单腿硬拉没有可参照的原文，画法由用户定（第九节第 7 问）；改不改正文由用户定。
- **骨质疏松**：不画单独的图。普通"扶墙"那一格按正文画成"背保持平、大腿后侧拉紧就停"（纯徒手 `moves.bw.md:227,230,232`，居家 `moves.home.md:227,230,232`），这和骨质疏松那一句"只下到背还能挺直的深度"（`safety.md:27,33`）一致，不另定"更浅"的深度。然后在规则表《条件变体》登记这一行，《共用图的级》的扶墙那一格就会显示。

图号只用于示意图，**不进动作索引**，不受批次 0"动作只增不改"的限制，也不会新增动作。

### 3.2 数据：不新增格式

上一版提议的两个新键都不需要了：

- 13–17 岁桌下划船照旧不显示（第 2.2 节）。
- 骨质疏松用现有的《条件变体》表登记（第 3.1 节）。表上方"对动作幅度有额外要求的不登记"这句改成"图上的幅度符合额外要求的可以登记，依据写原句"。

旧版和新版核心库读到的规则一样，不存在"旧版显示错图"的问题。

## 四、不能变的

| 范围 | 标准 | 怎么查 |
|---|---|---|
| 处方、阶梯、动作索引 | 一个字都不变 | **开发期间 `git diff dist/data/plans.json` 为空**（这才是"没动处方"的证据）；批次 0 的兼容检查同时证明动作和阶梯没动 |
| 成品正文 | 只多出插图的行和版本块标记，文字不变 | `git diff dist/*.md` 逐行看 |
| 插图的说明文字 | 不触发漏转核对：不写"数字 + 组 / 次 / 秒 / 轮"，也不写"背包、负重、不做、换成、升一级、下放 3 秒"这类词（`plans.py` 的漏转规则比数字更宽）。标题用"单腿硬拉：其他难度级"这类说法 | `tpl.py check` |
| 已有的图 | 87 张不变 | `tpl.py verify <改动前的 dist> --svg-tol 0.1`。这一批 `.md` 一定会变、新图算"多出"，所以它一定返回非 0；验收看**没有"不一致：img/…"** 这一类 |
| manifest | 只多出新图，`figures`、`products[].figures` 增加；插图位置之后的条目 `used_in[].line` 顺移是预期的；其余不变 | `git diff dist/manifest.json` 逐项看 |
| 已有的动图 | 原有片段的动画数据逐字节不变；只有第 2.3 节复用的片段，`exercises` 多出复用它的动作 | 比对 `motions.json` |
| 课程 | 除了清单里这些级多出 `figure`，其他都不变 | 导出快照：**第 a 步之前**用当前 `main`（含阶段 7）生成基线。忽略 `figure` 后 18,188 种情形 0 变化；不忽略时，变化全部是新增 `figure`，按汇总逐项对上第 2.1 节 |

## 六、分步

两个仓库各开 worktree（同上级方案第四节第 1 步）。新图不插进成品，`tpl.py check` 会报"这张图没有被任何成品引用"，提交前检查也会拦下，所以**每组的画图、插图、登记放在同一次提交**，审图在插图之前做。

| 步 | 内容 | 完成标准 |
|---|---|---|
| **0. 基线** | 用当前 `main` 生成导出快照基线，记下编排器大小 | 基线和当前比对 0 变化 |
| **a. 机制** | 主仓库：少了动图降为提醒、快照汇总。模板：`motions.py` 侧面按位置取、`_cell` 抽成共用函数、改坏自检 | `pushup-ladder.svg`、`motions.json` 不变；快照 0 变化；自检全部报出 |
