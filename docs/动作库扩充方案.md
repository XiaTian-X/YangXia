# 动作库扩充方案

> 状态：**r5，批次 0 已在分支 `movelib-batch0` 实施完成，待用户决定合并**（2026-11-19）。批次 1 没有开始，第八节其余问题还等用户定。实施记录见第十一节。
> 基于模板 v3.4。标"实测"的是真的跑过的（做法见第九节）；标"读代码"的是看代码得出的，没有单独跑。
> 另有一份并行草案 `docs/v4 阶段 7 细化方案（编排器：动作示意动图）.md`，两边的衔接见第五节末尾。

## 一、结论

1. **动作库可以扩，但不能现在就加动作。** 实测发现几类错误现有检查拦不住，比如把"8 次"导出成"8 秒"。要先补检查（第七节批次 0），再加第一个动作。
2. **每个新动作按一整包交付**：正文、示意图、索引、训练单、规则、主仓库联动、呈现验收，缺一项不算完成（第四节）。
3. **新动作默认不改变任何人现在的计划。** 使用者要自己有器材并选了它，或者到了成品写明的阶段，才会练到（第二、三节）。
4. **第一批只做单杠，但现在还不能动手**：这份方案可以作为批次 0 的依据；单杠要等"有器材才进入、到条件才开放"的机制设计好，并由用户确认放在哪份成品、哪些人不能做（第七、八节）。

## 二、七条底线

| # | 底线 | 为什么 |
|---|---|---|
| 1 | **动作发布后，ID、短名、计次 / 计时、是否每侧、图号都不改，也不删动作** | 档案、复盘、评估、练习记录、课程都存着 ID。改短名，旧课程马上报错（`plan.ts:585`） |
| 2 | **阶梯只能在末尾加级**；已有级的级号、名称、对应动作、起始级都不改 | 档案只存级号。实测：俯卧撑阶梯中间插一级，同一份档案的第 3 级从"跪姿"变成"上斜"，导出和课程检查都不报错 |
| 3 | **不动已有动作的处方**。要改，单独走一次处方修改，不夹在扩充里 | 否则分不清哪些变化是扩充带来的 |
| 4 | **处方不凭空写**。只有负荷和难度相当的动作才能沿用同一位置的处方；否则写进正文、登记 `设计值.md`、写明理由 | 同一行的选项共用组数、次数、休息（`plan.ts:449,465-468`）。把引体放进划船那一行，等于给它定了没有依据的处方 |
| 5 | **年龄段红线和适用条件不松**：65 岁以上不跳跃、不闭眼、不憋气，13–17 岁不谈体重和热量，40–64 岁不做跳跃和力竭；条件没确认的按保守版本 | `AGENTS.md`、成品安全须知 |
| 6 | **稳定期不新写处方**。新动作要进稳定期，必须从起始期正文进来，这会改变起始期成品（第八节第 4 问） | `templates/AGENTS.md` 第 9 条 |
| 7 | **声明不能少**：继续写"未经专业审核，不是医学建议，不能替代医生的判断" | 新动作同样没有专业审核 |

## 三、新动作怎么进计划：五种方式

每个动作立项时选一种。**从上往下优先**，越往下影响越大。模板发布后立刻作用于所有在途档案，没有"按档案锁定模板版本"这回事，下表的"影响"都按这一点写。

| 方式 | 准入条件 | 对在途使用者的影响 | 现状 |
|---|---|---|---|
| **A. 只进动作库**（替代动作） | 只在疼痛、器械被占时换着做，不进跟练 | 不改计划；但登记后会出现在 `course moves` 的列表里（`cli.ts:102`），要标清不能导出 | 正文已有，索引没有，解析规则认不出 |
| **B. 按器材选一个** | 同一位置；**计量相同、每侧相同、负荷和难度相当**，能共用组数、次数、休息 | 没选的人导出的动作、组数、次数、休息、节奏不变（实测）。**分组选项会自动带进 D 日循环**（`plans.py:822-826`），要在动作卡里决定 | 现有机制 |
| **C. 阶梯末尾加级** | 是同一动作的更难版本，计量相同 | 第 2 轮起，到顶的人马上可以升到这一级，不用改训练单的"级"列（实测，`plan.ts:202`） | 现有机制 |
| **D. 轮换** | 增加长期变化 | 发布后立刻按新成员计算（`plan.ts:396-398`）。**现在没有"到段或周期边界才生效"的机制**，要先做 | 机制不全，暂不用 |
| **E. 新增训练单一行** | 确实缺一个位置，由用户同意 | 所有人的计划都变，时长增加，要同步改取舍表 | 默认不用 |

## 四、每次扩充的标准工作清单

"谁来拦"：**自动**是现在就有检查，**批次 0** 是要补的检查，**人工**只能靠审查。

### 第 0 步：填动作卡（动手之前）

每个动作一张卡，放进这一批的细化方案：

| 项 | 内容 |
|---|---|
| ID、名称、别名、短名 | ID 用小写字母、数字、`-`；短名按第六节命名规则 |
| 用在哪 | 哪几份成品家族，如 `a18·bw、a40·bw`；同家族的稳定期成品会自动带上 |
| 接入方式 | 第三节 A–E 选一种，并说明符合准入条件 |
| D 日循环 | 进不进；现有分组选项默认会进，不进要先改代码 |
| 计量 | 计次或计时、是否每侧、是否左右交替（交替动作目前只能"照成品做"） |
| 节奏 | 发力、下放各几秒，能否写成课程格式；只有下放的动作要写清上去的方式 |
| 处方来源 | 沿用哪一行，或新登记哪个设计值 |
| 器材和门槛 | 要什么器材；第几段或达到哪条线才开放；怎么进 `choices` |
| 适用条件 | 高血压、骨质疏松、重度肥胖、40–64 岁等，逐项写不做、替换还是先问医生；条件没确认时走哪边 |
| 安全和疼痛 | 不适合谁、器材安全、哪里疼怎么处理，疼痛表要不要加一行 |
| 动作模式 | 补的是哪个缺口，和已有动作有什么不同 |
| 跟练动图（阶段 7 合并后） | 按次动作：有呼吸角标或登记节拍段才显示，否则不显示；计时动作：停在撑住姿势或循环；共用图的级要登记才显示 |

### 第 1–8 步

| 步 | 在哪改 | 做什么 | 谁来拦 |
|---|---|---|---|
| **1. 开独立工作区** | 模板仓库，要改代码时主仓库也开 | 用 git worktree 开分支，**不在共用目录切分支**：`git worktree add -b <分支> ../YangXia-<名> main`，再 `git -C templates worktree add -b <分支> ../../YangXia-<名>/templates main`。模板工作区放在主工作区的 `templates/`，**不靠环境变量**（漏设时真实模板测试会跳过，造成假通过）；每轮用 `node scripts/templates-path.mjs` 确认。主工作区运行 `npm ci`（`@yangxia/course-core` 是相对链接，不能共用）。确认提交前检查真的运行。模板工作区没有 `.venv`，用原目录的。`cp -R dist <临时目录>/dist-before` 留底 | 人工 |
| **2. 写正文** | `content/<读者>/moves.*.md` | 完整条目：练哪里、需要什么、做法、呼吸节奏、要点、常见错误、疼了怎么办；只给部分版本的用版本块 | 标题格式：自动；条目写全：批次 0 |
| **3. 改连带正文** | `train.*`、`gear.*`、`prep.*`、`log.md`、`warmup.md`、`head.md`、`next.md`、`adult-stable/*`、`products.md` | 训练框架、取舍表、休息、器材清单、准备、记录表、热身、封面说明、下一轮的方向；清掉变成错话的句子（第六节） | **人工**（实测不报错） |
| **4. 画示意图** | `figures/groups/*.py` | 在 `FIGS` 加同 ID 的图：两个视角动图、关键帧、错误示范、呼吸角标；撑住类动作加进 `PEAK_IDS`；新分组登记 `GROUP_ORDER` 和手册 `CHAPTERS`。阶段 7 合并后，动图只能用它规定的元素和动画属性（`line`、`polyline`、`polygon`、`rect`、`circle`、`ellipse`；`cx`、`cy`、`points`、`x1`、`y1`、`x2`、`y2`、`rx`） | 存在、被引用、红线词：自动；画得对不对：人工 |
| **5. 登记索引** | `content/动作索引.md` | 动作表加一行，"用在"写全；新的分组标题登记到第二张表 | 自动 |
| **6. 改训练单和规则** | `content/plans/`、`content/rules/`、`params/设计值.md`、`不影响训练单.md` | 改训练单、阶梯表；放慢规则、条件变体、评估、打卡里提到的同步；阶段 7 合并后还要改 `rules/动作示意.md`（共用图的级、条件变体、节拍段） | 和正文对不上：自动；计量、节奏：批次 0 |
| **7. 构建并看差异** | 模板仓库 | 见下面的命令；登记 `CHANGELOG.md` 的"未发布" | 自动 + 人工 |
| **8. 主仓库联动和验收** | 主仓库 | 见联动表和第六节 | 自动 + 人工 |

第 7 步的命令：

```bash
python3 tpl.py all
```

```bash
python3 tpl.py verify <dist-before> --svg-tol 0.1
```

```bash
git diff dist/manifest.json dist/data/
```

`verify` 只比成品 `.md` 和 SVG，不比 `manifest.json`、`data/`，所以第三条不能省。有新图时 `verify` 会报"多出"并返回非 0，这是预期的；要逐项确认差异都在动作卡列出的范围内。

### 第 8 步的主仓库联动

| 要做的事 | 在哪 | 什么时候要做 |
|---|---|---|
| 重新生成离线样例 | `node packages/course-core/test/make-fixtures.ts` | **每次**，而且用最终要合并的模板生成。实测：不重新生成，`fixtures.test.ts` 失败（共 773 项，其余 772 项通过） |
| 跑全量检查 | 每轮结束的自动检查查的是共用目录，工作区里要手动跑：`python3 tpl.py all`、`npm test`、`npx tsc --noEmit -p packages/course-core`、`npm run e2e`。e2e 只做回归，它用固定的深蹲、平板课程，测不到新动作 | 每次 |
| 导出快照比对 | 批次 0 新增的工具 | 每次 |
| 改 skill | `onboard`、`course-export` 写死了器材；`assess`、`weekly-review` 的"添装备"结论是使用者真正加器材的时候，要在那里更新 `choices` | 新增器材时 |
| 改数据约定 | `docs/数据约定.md`、`contracts/*.schema.json` | 改了格式或档案字段时 |
| 改核心库 | `packages/course-core/src/` | 现有格式表达不了时，**先于模板发版** |
| 更新总纲 | `AGENTS.md` 的进展和"模板要在 vX 之后" | 发版后 |

### 落地（由用户决定，要排队）

离线样例要和模板完全一致，只合一边 `npm test` 就会失败，还会挡住别的会话。所以落地是**一个连续动作**：

1. 确认没有别的分支正在落地，把两个分支 rebase 到最新的 `main`。
2. 重新生成离线样例，跑全量检查。
3. 用户同意后，模板分支合回模板 `main`，紧接着主仓库分支合回 `main`，中间不做别的。
4. 回到主目录，用默认的 `templates/` 再跑一次 `npm test`。

### 发版（由用户决定）

升成品版本号、写 CHANGELOG、更新 `README.md` 里的图数等数字、生成 PDF、打标签，然后主仓库更新样例和说明。两个仓库分别提交。版本号不提前占用，谁先合并谁用下一个号。

**每次发版对在途使用者的影响，要写进发版说明**：所有计划单都会报模板版本不一致，现在这一周的重新生成，以前几周的删掉（`sheet.ts:151-152`）；本周已导出的课程要重新检查，改过被引用的原句或周中改过 `choices` 的，要重新导出。

## 五、和其他工具的冲突点

| 工具 | 会出什么问题 | 现在拦得住吗 | 怎么避免 |
|---|---|---|---|
| **课程导出：计量** `plan.ts:466` | 计时动作放进"8–15 次"的行，导出 8 秒 | **拦不住**。模板和课程检查都 0 错误；只有条件全按正文一边的起点课程会多几条第二层警告（`plan.ts:542`），条件没确认的档案 0 警告 | 批次 0 第 2 项 |
| **课程导出：节奏** `plan.ts:474` | 选项写了自己的节奏也不生效，用这个位置的节奏 | **拦不住**（实测） | 批次 0 第 3 项：`sets` 行用选项自己的，**循环行继续用循环处写的** |
| **课程导出：读不出节奏** `plan.ts:476` | 动作悄悄转成"照成品做"，不进跟练；不写秒数、只写下放都读不出（实测） | **拦不住**；现有的 `a13-jump` 就是这样 | 批次 0 第 4 项 |
| **按器材选择和门槛** `plan.ts:405` | `choices` 不看门槛：还没开放的动作排在前面时，选中它后课程检查报错，不会退回下一个选项（审查实验） | 能拦下，但使用者走不下去 | 批次 1 先定退回规则 |
| **个人进度** `progress.ts:456,489` | 后来才开放的阶梯动作，建档只能在成品开始那天，稳定期找级也受限，起始级落不下来 | 能拦下，但走不通 | 批次 1 先定"第一次启用"的规则 |
| **进度、课程里的 ID 和级号** `plan.ts:431,585` | 改 ID、短名、插级后错位 | 大多**拦不住**。俯卧撑插级碰巧被 `check.py:861` 的"有基础俯卧撑级"挡住，换别的阶梯就拦不住 | 批次 0 第 1 项 |
| **适用条件** `plans.py:399` | 同一位置只能按**一个**条件分两行；高血压和骨质疏松同时要分时，构建失败（审查实验） | 能拦下，但表达不了 | 批次 1 先定多条件怎么写 |
| **安全筛查** `intake.ts` | 改筛查原话或加项，老档案报"少答"，导出也被挡 | 能拦下，老档案走不下去 | 默认不改筛查；要改须单独设计过渡 |
| **稳定期** `stable.py`、`exercises.py:197` | 训练单从起始期派生，索引要求起始和稳定成品里都有这个动作，**没有"只在稳定期才有"的通路** | 拦得住 | 写进起始期正文，开放由批次 1 的数据化门槛控制（第七节） |
| **健身房双进阶** `stable.py:344` | 周表定次数的主项会自动进双进阶 | 部分 | 动作卡写明，验收核对 |
| **大动作休息** `plans.py:678-680` | 名字不以大动作名结尾，休息会按小动作算 | 和正文比对时报错 | 改训练框架那句话，或注意命名 |
| **全量导出测试** `real-templates.test.ts` | 固定三个选项，新选项测不到；全扫约 252 秒，超过每轮检查的 180 秒上限（`.claude/settings.json`） | 拦不住 | 批次 0 第 5 项：分层 |
| **课程检查** `check.ts:186` | 用别的动作名的最后两字判断原文说的是谁，新名字可能多出提示 | 只影响第二层提示 | 看警告数有没有增加 |
| **导出门槛** `exercises.py:86`、`check.ts:345` | 标题里写"下一轮""第 N 周开始"就自动限制。新增的独立训练行标"下一轮才用"时，模板检查全过，但**第 1 轮所有人这一天都导不出课程**（审查实验）；而且轮次不等于达标，上一段走到第 4 周就算下一轮（`plan.ts:216-230`） | **拦不住** | 不能把标题当开放机制，用批次 1 的数据化门槛；标题用语按动作卡写 |
| **skill** | agent 不问新器材；居家版训练单是 `table-row / （门框划船）`，按 `onboard` 记 `door-row` 会导出报错（读代码 + 审查实验） | 拦不住 | 批次 0 第 10 项；第四节 skill 联动 |
| **示意图、手册** `make_figures.py:22`、`make_manual.py:24` | 新分组没登记，手册报错 | 拦得住 | 尽量放进现有分组 |
| **编排器** | 现在不认具体动作，不用改代码；名字影响画面。阶段 7 合并后按课程的 `figure` 显示动图 | — | 第六节验收 |
| **语音** `voice.ts` | 只念固定词和数字，不念动作名 | — | 无需处理 |

**发版顺序**：要改数据格式时，**主仓库先能读新格式，模板再发版**。读的一方会忽略不认识的字段，所以和安全有关的新字段不能只靠模板加。

**和阶段 7（动作示意动图）的衔接**：那份方案也还没批准，两边都要改 `plan.ts`、`check.py`、`real-templates.test.ts` 和离线样例。约定：各用独立 worktree，提交写明文件路径；开发不互等，落地按第四节排队，后落地的一方负责 rebase、重新生成样例并重跑全部验收；先后由用户定（第八节）。两边对"进跟练"用同一个定义（批次 0 第 4 项）。阶段 7 合并后，本方案第四、六节里标了"阶段 7"的项才生效。

## 六、呈现效果的验收标准

### 不能变的

| 范围 | 标准 | 怎么查 |
|---|---|---|
| 没用到新动作的成品 `.md`、已有 SVG | 开发时逐字节不变。改共用文件必须用版本块 | `tpl.py verify` |
| 发版时 | 只多出版本号、发布日期的变化 | `tpl.py verify <dist-before> --ignore-version --svg-tol 0.1` |
| `manifest.json`、`data/` | 只多出新动作相关内容，已有动作的条目不变 | `git diff` + 批次 0 第 1 项 |
| 没选新动作的档案 | 导出的动作、组数、次数、休息、节奏、原文出处都不变 | 批次 0 第 9 项的快照比对 |

### 每种成果怎么验

验收用的档案放在临时目录，**不用 `profiles/` 里的真实档案**。下面的命令都在第 1 步的工作区里运行。

| 成果 | 标准 | 方式 |
|---|---|---|
| **计划成品** | 动作库、训练框架、器材、准备、记录表、下一轮的方向说法一致；条目结构和相邻动作一样 | 通读 + `git diff dist/` |

### 批次 1：单杠（先做成人纯徒手版，居家版单独定）

**目标**：解决"建议买单杠，但计划里没有做法"的矛盾。

**候选动作**：悬垂、离心引体、标准引体。**不含弹力带辅助**：弹力带是另一种器材，示意图也没有这个道具（批次 3）。成品里"悬垂 → 弹力带辅助 → 离心引体 → 标准引体"这句要同步改。是否需要一个不靠弹力带的辅助级，在细化方案里定。

**建议的入口（待用户定）**：写进起始期正文的动作库，稳定期随之派生，不放宽"稳定期不新写处方"；开放由**数据化门槛**控制。徒手版封面的"零器械"改成"零器械起步，单杠可选"。

**标题写"下一轮才用"不能当开放机制**，它只是正文说明和课程检查的保险。单靠它，第 1 轮所有人这一天都导不出课程；整条阶梯全部延后，构建会失败（`plans.py:91-94`）；到了下一轮也不代表达标，成品的条件是完成 ≥ 14 练（`next.md`）。

**细化方案动手前必须解决，解决并经用户确认之前不动手**：

| 问题 | 为什么 |
|---|---|
| 放在哪个位置，替换还是并列 | 引体和划船难度差很多，不符合方式 B 的准入条件；不能简单放进 C 日划船行 |

| 第一次启用时的起始级 | 现有规则只允许成品开始那天建档 |
| 进不进 D 日循环 | 默认不进，代码要能表达 |
| 多条件同一位置怎么写 | 现在只能按一个条件分两行 |
| 离心的节奏和呼吸提示 | 格式需要发力和下放两段；课程把下放固定提示为"慢放吸气"，长时间离心是否合适要单独审，**目前没有专业依据** |
