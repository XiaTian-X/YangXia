## 一、要做什么

跟练时，编排器画面上显示**当前动作的示意动图**，动作跟着课程的发力、下放节拍走；实时跟练和导出的视频用同一套算法。

| 做 | 不做 |
|---|---|
| 复用现有 SVG 示意图，构建时转成 Lottie 动画数据 | 重新画图，或改现有 SVG 的画面 |
| 用 dotLottie 播放，按时间定到某一帧 | 手写动画引擎；把编排器改成 React / Remotion |
| 用 Mediabunny 替换手写的 WebM 封装 | MP4 导出（以后单独做）；对外联动、分享、账号、上传 |
| 课程里写明用哪段动图，由命令导出和核对 | 编排器按动作名猜图 |
| 没有合适动图、对不上节拍的动作不显示图，画面和现在一样 | 显示一张和这一级对不上的图；不跟节拍地循环播放按次动作 |

## 二、小样结论（2026-11-18，草稿目录，两个仓库没有改动）

用深蹲、俯卧撑、坐站起 3 个动作手工拼成单个 HTML，在 Playwright 的无头 Chromium 里断网运行。版本：`@lottiefiles/dotlottie-web` 0.82.1（MIT，2026-11-02 发布）、`mediabunny` 1.65.1（MPL-2.0，2026-11-03 发布），都满两周。

| 项 | 实测 |
|---|---|
| 转换 | 59 张图的第一个动图面板都能转；`a65-09-heel-toe-walk` 有一处整组淡出没处理（这个动作不进跟练） |
| 还原 | 3 个动作各比 8 帧，和浏览器画的同帧静态 SVG 比，线条像素里差异明显的最多 2.9% |
| 定帧 | 840×540，定帧加绘制中位约 0.8 ms，最慢约 7.7 ms；小数帧有效，来回跳结果一致 |
| 离线 | 断网打开，0 个网络请求，0 个页面错误；`setWasmUrl` 后不回退 CDN |
| 导出 | 1280×720、60 帧、带 Opus 音轨的 12 秒 VP9 WebM，用时约 1.6 秒、约 1.4 MB；读回时长 12.013 秒，编码、音轨都对 |
| 体积 | wasm 1.2 MB（gzip 491 KB）；两个库的脚本约 540 KB；59 段动画数据 2.6 MB（gzip 约 150 KB） |

带 SMIL 动画的 SVG 画到画布上只会得到同一帧（实测 3 个时刻结果相同），所以不能直接把现有 SVG 画进视频。

**还没验证**：真实 Chrome / Edge、较慢的电脑；真实的 Vite + singlefile + Preact 打包（7c 第一步先打通）；接入现有画面和真实音轨后的速度；一节完整长度课程的导出内存；俯卧撑分级片段。

## 三、整体结构

```
模板 figures → dist/img/*.svg（不变）
             → tools/motions.py → dist/data/motions.json（yangxia.motions/1）
content/rules/动作示意.md → rules.json 的 motion（哪一级能显示、节拍段）

course export → 课程的动作写 figure（这一级有合适动图才写）
buildTimeline → 时间轴多一列 motion（每段时间显示什么）

编排器构建 → 动图数据和 wasm 压缩后嵌进单文件
跟练 / 导出 → motionAt(时间) 算出"哪段动图的第几帧" → dotLottie 定帧 → drawHud 画到卡片里
```

四条约束：

1. **主仓库只读模板发布物**：动图数据由模板发布，主仓库不读 `figures/`。
2. **不猜**：只有从训练单导出的课程（有 `source.plan`）才用 `figure`；图号还要和这个动作对得上。
3. **老东西照常**：旧模板、旧课程、手写课程、编辑器新建的动作都能用，只是没有图。
4. **任何一步失败都退回无图**：解压、wasm、动图加载失败都不影响报数、声音、导出。

## 四、模板（7a）

### 4.1 什么叫"进跟练"

**进跟练 = 训练单标了可导出，并且核心库读得出呼吸节奏（或者是计时动作）。** 动作库扩充方案批次 0 第 4 条用同一个定义。

审查用真实 `exportCourse` 扫了 69,288 种组合：实际进课程的是 **48 个动作：44 个按次、4 个计时**。`a13-jump` 标了可导出，但节奏读不出，走"照成品做"，不进课程；批次 0 打算把它改标"照成品做"。模板不解析节奏，所以在 `content/rules/动作示意.md` 里把它列为"不生成"，由主仓库的双向核对兜底（5.4）。

### 4.2 动图数据 `dist/data/motions.json`

```json
{
  "format": "yangxia.motions/1",
  "version": "v3.x",
  "clips": {
    "squat": {
      "exercises": ["squat"],
      "frames": 48, "dur": 4.0, "w": 420, "h": 270,
      "phases": { "top": [47, 7], "down": [6, 24], "bottom": [30, 5], "up": [35, 12] },
      "lottie": {}
    },
    "plank": { "exercises": ["plank"], "frames": 48, "dur": 4.0, "w": 420, "h": 270, "hold": 20, "lottie": {} },
    "gym-farmer-walk": { "exercises": ["gym-farmer-walk"], "frames": 48, "dur": 4.0, "w": 420, "h": 270, "loop": true, "lottie": {} }
  }
}
```

（数字是格式示例。）

- 键是片段号，现在等于图号。`exercises` 是能用这段动图的动作，编排器据此防错图号。
- 按次动作必须有 `phases`（"从第几帧出发、走几帧"，可以跨循环点）；计时动作有 `hold`（撑住的那一帧）或 `loop: true`。
- 取每张图的第一个动图面板（按"动图"角标找，不写死坐标），去掉文字和角标，保留底色、地面、人和器材。
- 新脚本 `tools/motions.py`，只用 Python 标准库，放进 `tpl.py all` 和 `expected_outputs`（这样才查新鲜度）；manifest 的 `data` 登记。

### 4.3 规则表 `content/rules/动作示意.md`

发布到 `rules.json` 的 `motion`。按家族代码（`a18·bw` 等）登记：起始期和稳定期的阶梯相同、代码也相同，不分开写。

**表一：共用图的级。** 同一条阶梯里有两级以上指向同一个动作，这些级就算共用图，**登记了才显示**。级号和级名都写，`check.py` 对照 `plans.json` 逐级核对，防止级号错位。

| 家族 | 阶梯 | 级号 | 级名 | 片段 |
|---|---|---|---|---|
| a18·bw、a40·bw | squat | 1 / 2 / 3 | 徒手 / 下放 3 秒 / 底部停 2 秒 | squat |
| a18·home、a40·home | squat | 1 / 2 / 3 | 同上 | squat |
| a13·bw | squat | 2 / 3 / 4 | 徒手 / 下放 3 秒 / 底部停 2 秒 | squat（第 1 级坐椅深蹲不显示） |
| a18·bw、a18·home、a40·bw、a40·home、a13·bw | pushup | 4 / 5 | 标准俯卧撑 / 下放 3 秒的标准俯卧撑 | pushup（1–3 级和第 6 级不显示） |

（上表是例子。一共 11 个动作涉及共用图，实施时**逐张看图**填写。只改节奏的级可以显示；换了支撑、负重、单腿的不显示。）

**表二：条件变体。** 训练单里不是正文那一边的条件行（判定和 `plan.ts` 现有的 `variant` 相同），默认不写 `figure`，看过图、登记了才写。例如高血压版的 `plank`、`wall-sit` 看图没问题就登记；骨质疏松版的 `sl-rdl` 原句要求"只下到背还能挺直的深度"，图上的幅度可能不符，不登记。条件没确认时导出的是保守版本，所以这张表决定多数人看不看得到这些动作的图，要填全。

**表三：节拍段。** 图上有呼吸标签的自动判断（呼气段 = 发力，吸气段 = 下放，段内不动的部分算停顿），44 个按次动作里 35 个能自动判断。其余 9 个写明帧区间：

| 情况 | 动作 | 做法 |
|---|---|---|
| 图上没有呼吸标签 | `a65-01`～`a65-05`、`a13-sl-rdl-wall`、`a13-pike-high`、`a13-bar-row`（8 个） | 看图写帧区间，不改 SVG。`a65-01` 其实是三段（前倾 6–20、站起 22–41、坐下 51–87）：发力取 6–41，人工确认 |
| 一轮里还有上下凳 | `split-squat-stool` | 只取中间：`down [35,24]`、`bottom [59,4]`、`up [63,12]`。第 35 帧和第 75 帧姿势相同，第 59 帧和第 63 帧姿势相同。循环整段会让人以为每次都要上下凳 |

**不生成**：`a13-jump`（4.1）。

**计时动作**：取片段里最长的静止段做 `hold`，不依赖呼吸标签；连续动作（`gym-farmer-walk`）在表里写"循环"。

俯卧撑前几级是新手最常用的。`pushup-ladder.svg` 每一级都有小动图，7a 评估能否拆成按级的片段（如 `pushup-ladder#1`）。拆不好就不显示，不拿标准俯卧撑顶替。

### 4.4 转换器支持的范围

元素：`line`、`polyline`、`polygon`、`rect`、`circle`、`ellipse`。动画属性：`cx`、`cy`、`points`、`x1`、`y1`、`x2`、`y2`、`rx`。遇到别的元素、属性或动画一律报错，不静默丢掉（新器材的图由此能及时发现）。

### 4.5 模板检查（`tpl.py check`）

- 训练单可导出的动作都有片段，或者列在"不生成"里；片段引用的图和动作都存在。
- **逐帧数值核对**：Lottie 关键帧插值的坐标和 SVG 每一帧相差不超过 0.25 像素（全部片段，不依赖浏览器）。
- 按次动作都有闭合的 `phases`，发力、下放成对；计时动作有 `hold` 或 `loop`。
- 规则表里的家族、阶梯、级号、级名、片段都对得上。
- 改坏自检：节拍登记错、删片段、加不支持的元素、级名对不上、级号错位，都要报错。

SVG、成品 `.md`、训练单都不变。

## 五、课程和核心库（7b）

### 5.1 课程 `items[].figure`（可选）

- `course export` 写入：有片段，且（不是共用图，或表一登记了）且（不是条件变体，或表二登记了）。
- `checkPlanCourse`：写了就要和重新导出的一致。导出有而课程没有时：同一版模板导出的课程报错（说明被改过），更新模板之前导出的旧课程只提醒（照常能用，重新导出才有图）。
- 没有 `source.plan` 的课程写了 `figure`：`course check` 报错；编排器忽略。
- 编辑器改动作名称、计次方式时，当场删掉这一项的 `figure`。不靠 `edited` 判断（方案库载入时它会重置）。
- `contracts/course.schema.json`、`validate.ts` 加这个字段（小写字母、数字、`-`、`#`）。

### 5.2 时间轴 `timeline.motion`

`buildTimeline` 多返回一列，**不改 `events`**（报数、声音、字幕、原版基线都不受影响）：

```ts
type MotionSpan = { itemIndex: number; start: number; end: number; note: MotionNote } & (
  | { kind: "phase"; phase: "up" | "top" | "down" | "bottom" }
  | { kind: "timed" }
  | { kind: "pose"; pose: "start" | "last" }
);
type MotionNote = "ready" | "doing" | "switch-side" | "next-set" | "next-item" | "done";
```

课程的每一秒都要落在某一段里：

| 时段 | span | 画面 | 卡片小字 |
|---|---|---|---|
| 开课准备、倒数 | `pose:start`，第一个动作 | 起始姿势 | 准备 |
| 按次动作的每一拍（同相位的多拍合并） | `phase` | 对应相位 | 动作示意 |
| 每组最后一次多出的等待 | `pose:last` | 这一次结束的姿势 | 动作示意 |
| 计时进行中 | `timed` | 撑住帧；`loop` 的原速循环 | 动作示意 |
| 计时完成后的 1.85 秒 | `pose:last` | 撑住帧；`loop` 的回第 0 帧 | 动作示意 |
| 每侧动作中间换边的 2 秒 | `pose:start` | 起始姿势 | 换另一侧 |
| 同一动作的组间休息、下一组准备 | `pose:start` | 起始姿势 | 下一组 |
| 换动作前的休息、准备 | `pose:start`，下一个动作 | 下一个动作的起始姿势 | 下一个 |
| 课程结束后的尾巴 | `pose:last` | 最后姿势 | 完成 |

每侧动作的卡片加"示意一侧"：图不镜像，由现有的"左侧 / 右侧"文字提示练哪边。

### 5.3 算帧 `motionAt`（纯函数，放新文件 `figure-motion.ts`）

起始姿势：按次动作是 `phases[tempo.start][0]`，计时动作是 `hold`（`loop` 的是第 0 帧）。

| 情况 | 结果 |
|---|---|
| 课程在某一相位，片段有这一段 | 按进度映射到对应帧；课程秒数和动图秒数不同就伸缩 |
| 课程有这个停顿，片段没有 | 停在分界那一帧 |
| 片段有这个停顿，课程没有 | 跳过（审查实测前后姿势差为 0，不会跳变） |
| 没有 `source.plan`、没有 `figure`、片段不存在、`item.exercise` 不在片段的 `exercises` 里 | 返回空，不显示 |

### 5.4 契约和样例

- `contracts/templates.json` 的 `data` 项加 `optional`，`motions.json` 标可选；`fixtures.test.ts` 跟着改。没有这个文件时不报错，只是没有图。
- `make-fixtures` 生成 2–3 段的离线片段：模板不在时单元测试和 e2e 也能测。
- `real-templates` 加双向核对：导出的 `figure` 都有片段，片段都有课程用。日常跑每个选项、每个可用级至少一次，全量扫描放发版前的命令（全扫超过每轮检查的 180 秒上限；分层可以和动作库批次 0 第 5 项共用）。

## 六、编排器（7c）

第一步先打通真实打包：Vite + singlefile 里嵌 wasm、`setWasmUrl`、断网跑一个片段。

| 模块 | 做法 |
|---|---|
| `src/figure/clips.ts` | 构建时由 Vite 虚拟模块带入 gzip 后的动图数据和 wasm，用 `DecompressionStream` 解开。模板不在时是空表，照常构建；e2e 用环境变量指定离线样例 |
| `src/figure/player.ts` | 每段动图一个 dotLottie，放在 `OffscreenCanvas`（840×540）。**课程载入时预载这节课用到的片段（去重）** |
| `src/hud/draw.ts` | `drawHud` 增加可选的 `figure` 参数，**不传时输出和现在一样** |
| `Settings.tsx` | 加"显示动作示意"，存进 `PlaybackSettings.motionFigure`，判断用 `!== false`（旧方案库的设置没有这一项） |

- 实时：片段没加载好就先不画卡片。
- 导出：开始前等所有片段就绪；个别失败的只是不显示，其余照常。
- 失败时给一句提示，不打断跟练。

**画面位置**（1280×720）：

- 左下角卡片布局：图放右侧空白区，约 x 610–1230、y 150–550，浅色不透明圆角卡片。
- 居中布局：有图时主卡片左移、图放右边；没图时和现在完全一样。具体尺寸实施时对照画面定。
- 卡片底部小字：动作提示（5.2），以及**"未经专业审核，不是医学建议，不能替代医生的判断"**（视频离开页面后声明还在）。
- 48 张面板含绿色：绿幕抠像可能受影响，设置里的说明提示用品红幕（默认导出就是品红幕）。

## 八、离线、隐私、授权

- `setWasmUrl` 必须在首次使用前指向内嵌的引擎（库里写着 CDN 地址）。
- **构建时**给页面注入内容安全策略（不写进 `index.html`，以免影响 `npm run dev`）。下面这组审查实测通过（`file://`、断网，小样全流程和现有编排器的跟练、SRT、WAV、WebM 导出）：

  `default-src 'none'; script-src 'unsafe-inline' 'wasm-unsafe-eval'; style-src 'unsafe-inline'; img-src data: blob:; media-src blob: data:; connect-src blob: data:; worker-src blob:; font-src data:; base-uri 'none'; form-action 'none'`

  录报数声、导入音乐、系统语音在这组策略下还没测，7c 要测。
- e2e 断言跟练和导出全程 0 个外部请求。编排器不记录、不上传任何内容，这一点不变。

## 十、开发和落地

两个会话不共用工作区：

```bash
git worktree add -b v4-phase7 ../YangXia-phase7 main
```

```bash
git -C templates worktree add -b v4-phase7 ../../YangXia-phase7/templates main
```

- 模板 worktree 直接放在主 worktree 的 `templates/`（已被忽略），**不用 `YANGXIA_TEMPLATES`**：环境变量漏设时模板相关测试会被静默跳过。每轮测试前用 `node scripts/templates-path.mjs` 确认指向这里。
- 主 worktree 运行 `npm ci`。`core.hooksPath` 是仓库共用配置，不重新设置；第一步先确认提交前检查在 worktree 里真的运行，不能运行就停下来处理，不绕过。
- 每轮结束的自动检查查的是共用目录，所以在 worktree 里手动跑全量：`python3 tpl.py all`、`npm test`、`npx tsc --noEmit -p packages/course-core`、`npm run e2e`。
- 共用目录里的未提交文件不碰；提交一律写明文件路径，不用 `git add -A`。

**开发不互等，落地要排队。** 离线样例要求和当前模板的 `rules.json` 完全一致，只合一边 `npm test` 就会失败，还会拦住另一个会话。所以每次落地是**一个动作**：

1. 确认另一边没有在落地；把两个分支 rebase 到最新的 `main`。
2. 在 worktree 里重新生成离线样例，跑全量检查。
3. 用户同意后，模板分支合回模板 `main`，紧接着主仓库分支合回 `main`，中间不做别的。
4. 版本号这边不占，谁先发谁用下一个，由用户定。
