## 二、课程包

### 2.1 是什么

就是平时那个 `养夏跟练编排器.html`，在里面多放一段**不执行的 JSON**：

```html
<script type="application/json" id="yangxia-course">{…这节课…}</script>
```

- 打开时编排器读这一段，有课程就直接载入，"今天"页显示这节课（和导入 JSON 后一样，照样走 `validateCourse`，不合格就显示错误、不载入）。
- 没有课程（普通编排器）就是现在的行为。
- "换一节课"、方案库照常能用（决定 3）；"换一节课"也认课程包 `.html`（从里面取课程）。
- 页面标题在运行时设成 `养夏 · <课程名>`（`document.title`，不用做 HTML 转义）；普通编排器的标题不变（e2e 查它）。
- "今天"页写一行"课程包 · 11 月 24 日导出"（导出日期由 `packCourse` 写在嵌入块的 `data-exported` 属性上，不写进课程，不影响"和 JSON 完全一样"）。

**内容安全策略不改**：`type="application/json"` 的 script 不执行，`script-src` 管不到它；读它用 `textContent` + `JSON.parse`，不用 `eval`。

**转义**：`JSON.stringify` 之后把每个 `<` 写成 `\u003c`（反斜杠 u003c 这六个字符）。JSON 在字符串外不会出现 `<`，所以 `</script>`、`<!--` 都截不断；`JSON.parse` 还原后一字不差。U+2028、U+2029 对不执行的数据块和 `JSON.parse` 没有影响，不另外处理。

**写死的实现细节**：

- 打包时（vite 构建的最后一步，单文件内联之后）往页面里写：
  - `<meta charset>` 之后一个 `<meta name="yangxia-package" content="format=yangxia.package/1;motions=v3.4;motionsHash=…;source=…">`（第 2.2 节说每项是什么），不把 charset 挤出前 1024 字节；
  - `</body>` 前一个空的嵌入块 `<script type="application/json" id="yangxia-course"></script>`。
  - 打包测试断言这两样各**只出现一次**（内联的 JS 里不能出现完整的标记字面量，代码里用拼接的写法找它）。
- 嵌入、读出都是 `course-core` 里的纯函数（`packCourse(html, course, exportedAt)`、`unpackCourse(html)`、`packageInfo(html)`），CLI、档案检查、e2e 共用。
  - 替换用下标切片拼接，不用 `String.replace` 传字符串（避免 `$&`、`$'` 被当成替换模式）。
  - 只认**恰好一个**嵌入块和一个标记：零个或多个都报错；读出来的内容里出现生的 `<` 也报错（防止检查读的和页面载入的不是同一份）。
  - 对已经嵌过课程的 HTML 再嵌：报错（只从空的编排器出课程包）。
- 编排器那边用 `querySelectorAll('script#yangxia-course')`，数量不是 1、或者内容不是合格课程，显示错误、不载入。

### 2.2 `course export` 怎么出

现在的流程不变（先查档案、导出、课程检查 0 错误才写 JSON）。写完 JSON 以后：

1. 找打包好的编排器：默认 `apps/sequencer/dist/养夏跟练编排器.html`，环境变量 `YANGXIA_SEQUENCER` 可以覆盖（和 `YANGXIA_TEMPLATES` 一样）。单元测试不依赖本机有没有打包：测试时用共用的哈希函数**现算**当前的源码哈希和动图哈希，拼出一个最小的假编排器 HTML（不提交固定的夹具，不然源码一改、动图一更新测试就坏）；改坏其中一项就是"过期""动图对不上"的用例。
2. 读它的标记，核对能不能用：
   - `format` 要是 `yangxia.package/1`。
   - **动图对得上**：`motionsHash` 要等于现在模板 `dist/data/motions.json` 内容的哈希（模板的版本号只在发版时变，没发版的动图更新版本号不变，所以比内容）；`motions`（版本号）要等于课程的 `source.templates`。打包时没带动图（`motions=none`）也不行。
   - **编排器不过期**：`source` 是打包时会进编排器的源码的哈希，导出时用同一个算法重算（共用 `scripts/` 下的一个函数），不等就是代码改过、没重新打包。算法写死：
     - 范围：`apps/sequencer/src`、`apps/sequencer/index.html`、`apps/sequencer/vite.config.ts`（内容安全策略、动图内嵌）、`apps/sequencer/package.json`、`apps/sequencer/third-party/`、`packages/course-core/src`、根目录 `package-lock.json`（依赖版本）、`contracts/fixtures/courses/ok-a18-home-w1-a.json`（编排器里的样例课）。`packages/course-core/src` 里有命令行这类不进编排器的文件，改了也要重新打包——偏保守，sequencer-dev skill 里说明。
     - 文件清单：`git ls-files --cached --others --exclude-standard -- <这些路径>`（含还没 `git add` 的新文件），跳过已经删掉的；按路径排序。
     - 内容读**工作区**的文件（不是 git 里存的版本）：有未提交的改动也算进去，打包以后又改了代码就能查出来。
     - 每个文件拼成 `路径\0长度\0内容`，整体算 SHA-256。
     - 算不出来（不是 git 检出、没装 git）：当作过期，不出课程包，打印原因。
3. 能用就把课程嵌进去，写课程包（文件名见 2.4），打印"已导出课程包：…，课程包里只有这节课的内容；发给自己的手机（文件传输助手、AirDrop、数据线），不要发到群里"。
4. 不能用（没打包、过期、动图对不上、格式不认识）：**只写 JSON**，打印为什么没出、怎么办（`npm run build` 以后重新导出），命令照样成功（决定 1）。**同名的旧课程包删掉**并打印"旧课程包已删：它和新课程对不上"——不然旧的（可能更重的）课程包会留着被发出去。
5. `--out` 指定了 JSON 路径的，课程包放在同一个目录：`.json` 结尾的换成 `.html`，别的直接加 `.html`；加 `--no-package` 不出课程包（同样删掉同名旧课程包）。

核心库不 import 编排器的代码，只读它的构建产物（和读模板的 `dist/` 一样）。

### 2.3 档案检查认得它

`profile check` 扫档案目录时，`.html` 现在报"不认识的文件"。改成：

- `课程/` 和 `历史/第N段/课程/` 下的 `.html` 当课程包：
  - 读不出标记或嵌的课程（`unpackCourse` 报错）→ **错误**："不是养夏课程包（或者是旧版编排器）：删掉，或者重新导出"。
  - 嵌的课程要和对应的 JSON（2.4 的对应规则）**完全一样**（按 JSON 内容比，不比格式）→ 不一样是**错误**："课程包和课程 JSON 对不上：重新导出"；没有对应的 JSON 也是错误（课程检查只认 JSON，不能让课程包躲过检查）。
  - 标记里的 `motions` ≠ 课程的 `source.templates` → **错误**。只比版本号，不比哈希：版本号和课程都随课程包定死，以后模板更新不会让 `历史/` 里的课程包误报。
  - 嵌的课程不重复跑课程检查（它和 JSON 一样，JSON 那边已经查了）。
- 带课程包标记的 `.html` 出现在 `课程/` 以外 → **错误**（"课程包放在 课程/ 下"）；别的 `.html` 照旧报"不认识的文件"。
- `课程/` 里以前几周的课程包（不是现在这一段这一周的）→ **提醒**："以前几周的课程包，复盘完可以删（课程 JSON 留着）"（决定 7 由代码查）。
- `cli.ts` 里"旧课程比现在重，删掉或者重新导出"的提示改成"连同同名课程包一起删掉，或者重新导出"。

### 2.4 文件名

| 文件 | 现在 | 改成 |
|---|---|---|
| 课程 JSON | `课程/第N段-第N周-X日.json` | 半量课加 `-半量`：`课程/第N段-第N周-X日-半量.json`（决定 6；半量课和全量课 `id` 不同，以前写同一个文件名会互相覆盖） |
| 课程包 | — | `课程/<代号>-第N段-第N周-X日[-半量].html`（决定 5：一家人的课程包到了手机上要分得清；代号不是真名） |

- **代号**取档案的 `code`（就是 `profiles/` 下的目录名）。代号会跟着文件到手机、聊天软件里：建档时提醒不要用能认出人的称呼（onboard skill）。代号里有 `: * ? " < > |` 这类部分手机文件系统不能用的字符，文件名里换成 `_`。
- `--out` 指定路径的：课程包同目录、同名（`.json` 换成 `.html`，别的加 `.html`），不加代号。
- **对应规则**（档案检查找课程包的 JSON）：先找同名（去掉 `.html` 加 `.json`）的 JSON；没有就按名字后半段认——`^(?:.+-)?(第\d+段-第\d+周-.+日(?:-半量)?)\.html$` 的第 1 组加 `.json`。档案目录改过名、代号变过，以前的课程包照样对得上。

### 2.5 隐私和安全

- 课程包只嵌课程本身（和 JSON 一样），不放档案、练习记录、筛查。上级方案第六节已经说明 `coaching` 不写病情；r1 审查探测了 320 份导出课程（各种条件取是和否），正文里没有高血压、骨质疏松、BMI、医生字样，只有 `coaching.floor` 间接透露一点。
- 课程包、练习记录会在电脑和手机之间来回（经过聊天软件）：导出、导入时都提醒"发给自己，不要发到群里"；导入成功后提醒原文件还在下载目录、手机、聊天记录里，可以删（个人数据只放在 `profiles/`）。AGENTS.md 隐私一节加这一条。
- 课程包和普通编排器一样离线：不联网，内容安全策略不变，e2e 断言 0 个外部请求。

### 3.1 编排器这边

8b 已经做了：练完页"保存练习记录"（下载）和分享按钮（系统分享，不行就下载）。8c 改说明文字：

- 保存后的提示（现在写"放进 profiles/<代号>/打卡/"）改成"已保存：发回电脑，交给 agent 导入"。

### 3.2 练习记录的格式校验补齐

`validateSession` 现在不查 `endedAt`、`note`、`skipped`、`course.id` 的写法和 `course.source` 的内容，而下游要用 `source`（半量周 `source.half === true`、轮换计数 `source.day`/`source.segment`、周次 `source.week`）。补齐：

- `endedAt` 是时间、不早于 `startedAt`；`note` 是不超过 500 字的字符串（按码点数，和 ajv 一样；编排器那边截断也按码点）；`skipped` 是布尔、等于 `setsDone === 0`。
- `course.id` 符合 `^c_[a-z0-9]{6,40}$`（和课程格式一样）。
- `course.source` 照 `course.schema.json` 的 source 定义逐项查类型：`product`、`templates`、`week`、`day`、`plan`、`segment`、`type`、`phase`、`picks`、`half`（`half` 只能是 `true`）；不认识的项报错。`contracts/session.schema.json` 的 `course.source` 改成引用课程格式的 source 定义。
- 为了两边一致，**课程格式的 source 也加 `additionalProperties: false`**，`validateCourse` 同步报不认识的项（现有课程样例和导出的课程都没有多余的项，已核实）。以后（比如阶段 9）给 source 加字段，课程格式、练习记录、两个校验函数一起改。
- 照 `conformance.test.ts` 里课程那份，给练习记录加"ajv 按 schema 判和 `validateSession` 判一致"的测试，补不合格样例（`contracts/fixtures/sessions/bad-*.json`）。

这样档案检查（`scanDir` 已经对每份记录跑 `validateSession`）和导入命令一起变严。已有的练习记录如果不合格，档案检查会报出来（以前漏掉的问题），照提示改或重新导入。

### 3.3 导入命令

```
npm run profile -- import profiles/<代号> <记录.json> [更多记录.json…]
```

对每个文件：

1. **读**：不是文件、大于 1 MB、JSON 解析不了 → 拒收（只报"解析不了"，不打印文件内容）。
2. **校验格式**：`validateSession`（3.2 补齐后的）有错误 → 拒收，打印错误。
3. **不适先报**：只要 JSON 读得出来、`symptoms` 里有 `true`，不管后面收不收，都醒目地打印"这次有疼痛 / 头晕 / 胸闷：下周不加量，按成品'疼了怎么办'处理；胸痛胸闷、头晕站不稳要建议就医"。被拒收的记录有不适时，再加一句"这份记录没导入：周复盘时照实写进复盘数据的 symptoms"。
4. **练的是不是这个档案的课**：
   - `course.source.plan` 要有（从训练单导出的）——样例课、手写课没有，拒收（决定 2）。
   - 用 `source` 里的成品、段、段型、周、日、半量**重算 `id`**（导出时同一个算法，`plan.ts` 的 `hash` 导出来用），要等于记录的 `course.id`——防止手改。
   - 档案的 `segments` 里要真有这一段（`n`、`product`、`type` 一样）和这一周（`week` 不超过这一段已经开到的周）。不要求课程文件还在：半量课覆盖、"旧课程比现在重"删掉以后，练那一份的记录照样能导入。
   - **已知限制**：一家人用同一份成品、同一段同一周同一天，课程 `id` 一样，拦不住"把别人的记录导进来"。由 agent 导入时核对来源（问使用者这是谁练的）。
5. **时间**：`startedAt` 不晚于现在（留 5 分钟时钟误差），不早于这一段开始那天（按本地日期比，和 `periodIndex` 一样）。
6. **去重**：先按 3.2 规范化，再和档案里**所有**练习记录比（`scanDir` 的 sessions，含 `历史/第N段/打卡/`、文件名带"(1)"这类的）：
   - `course.id` 和 `startedAt` 都一样、内容完全一样 → 跳过，打印"已经导入过"。
   - `course.id` 和 `startedAt` 都一样、内容不一样 → 拒收，打印哪几个字段不一样（`symptoms` 放最前）和旧记录在哪，让人看一眼再决定。确实要换（比如后来补报了不适）：由 agent 问过使用者，加 `--replace` 再导入——**在旧文件原来的路径上原地覆盖**（不改文件名，`progressLog.evidence` 引用的依据还在），打印改了哪些字段。
   - 两边都先规范化再比（档案里已有的记录也一样）。
7. **写进档案**：按 3.2 的字段和固定顺序重写，多出来的字段丢掉，打印丢了哪些字段名（不打印值）。文件名 `打卡/养夏_练习记录_<日期>_<时分>.json`（按 `startedAt` 的本地时间，和编排器下载的文件名一样）；这个名字已经被别的记录占了（同一分钟练两次），加 `_2`、`_3`。
8. **备注**：有 `note` 就原样打印出来，交给 agent 按 AGENTS.md 隐私核对。为了先看后写，命令有 `--dry-run`：只打印不适、备注、校验结果和要写到哪，不写文件。skill 里的顺序是先 `--dry-run`，备注里有病名、用药、血压体重数字的，问使用者删掉那几句（agent 改原文件里的备注）再正式导入。

整批导完以后跑一遍完整的档案检查（和 `profile check` 一样，含 `checkProgress`），照常打印问题。说明：

- 导入**不回滚**：档案本身有错（以前就有）也照样导入记录，错误照常报出来。
- 晚到的记录落进**已经复盘过的那一周**，会让那一周的复盘数据报错（训练次数少于练习记录数、有不适却写没有）：打印"第 N 周的复盘要改：…"。
- 一个文件拒收，退出码非 0，但别的合格文件照样导入。原文件不动（决定 4），导入成功后提醒可以删。

导入命令只在本机读写文件，不发往任何地址。agent 照 AGENTS.md 如实告诉使用者：agent 读记录时内容会作为对话发给模型服务处理。

### 3.4 拦得住什么（测试逐条有用例）

格式标识不对；缺字段、类型不对；`endedAt` 早于 `startedAt`；`--dry-run` 不写文件；`--replace` 原地覆盖、文件名不变；备注超长或不是字符串；`skipped` 和完成组数矛盾；完成组数超过计划；感受不是成品原话；症状不是 true/false；`course.id` 写法不对；`source` 有不认识的项、`half` 不是 `true`；`id` 和 `source` 重算对不上；没有 `source.plan`；档案里没有这一段、这一周；`startedAt` 在将来或早于这一段；同 `id` 同 `startedAt` 内容不同；JSON 解析不了；不是文件或大于 1 MB。另有：拒收的记录有不适时照样提醒；同一分钟两份记录都收下；导入以后那一周的复盘报错时打印要改。
