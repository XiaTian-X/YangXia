<h1 align="center">养夏 YǎngXià</h1>

<p align="center">帮人从<b>作息、锻炼、饮食</b>三方面建立习惯，由 AI agent 驱动。</p>

> **这些计划不是医学建议，不能替代医生的判断。** 有慢性病、伤病、怀孕等情况，先问医生。计划目前**没有专业人员审核**。

> **版本说明：这是养夏最后一个"本地优先、离线"的版本**——主仓库 **v1.0.0**（标签 `v1.0.0`，2026-11-24），配**模板 v1.0.0**（模板仓库的标签 `v1.0.0`）。所有数据和工具都在你自己的电脑上：agent 在本机用命令行工作，跟练编排器是一个双击就能打开的离线网页，课程包发到手机上跟练，练习记录发回电脑导入。之后养夏转为**自托管版**的架构——服务端、网页排课、原生手机跟练——另写方案。这一版的能力和边界见下面的[这一版能做什么、不能做什么](#这一版能做什么不能做什么)。

## 养夏 YǎngXià 是什么

养夏 YǎngXià 把三样东西串起来：

- **内容**来自**养夏计划模板**：按年龄段和场地分的计划——四周一段的起始期，成人、13–17 岁、65 岁以上还有 12 周一个周期的稳定期；运动、三餐、睡眠都有，官方数字取自 WHO、国家卫健委等官方文件，出处写在每份计划末尾。
- **跟练**用**养夏跟练编排器**：带语音报数、呼吸提示和动作示意动图的跟练页（手机、平板、电脑都能用），也能导出跟练音频、视频和字幕。
- **agent**（Claude Code）负责建档、选计划、导出跟练课程、周复盘、排菜单。它只在模板规则之内定制：课程里的组数、次数、休息都来自成品原文，由检查命令逐项核对。

| 使用者 | 场地 | 成品 | 能不能导出跟练课程 |
|---|---|---|---|
| 6–12 岁（小学生，家长使用） | 户外、家里、学校 | `6-12岁-户外与游戏版（家长版）` | 不导出，照成品原文做 |
| 13–17 岁（初中生、高中生） | 家里或操场，零器械 | `13-17岁-纯徒手版` | 能 |
| 18–39 岁 | 健身房 / 居家（2.5kg 哑铃 + 动感单车）/ 纯徒手 | `18-39岁-健身房版`、`18-39岁-居家版`、`18-39岁-纯徒手版` | 能 |
| 40–64 岁 | 健身房 / 居家（2.5kg 哑铃 + 动感单车）/ 纯徒手 | `40-64岁-健身房版`、`40-64岁-居家版`、`40-64岁-纯徒手版` | 能 |
| 65 岁以上、能自己走路 | 家里两把椅子 + 厨房台面 + 户外平路 | `65岁以上-椅子辅助版` | 能 |
| 全家一起吃饭 | — | `全家餐饮模板`（配套的 `三餐菜谱手册` 只适用于 18–64 岁） | 不涉及，用来排菜单 |

- 18–64 岁、13–17 岁、65 岁以上起始期练完一段、到了进阶线的（成人有基础、测试达线的也可以建档时直接进），换成同一份的"（稳定期）"成品：12 周一个周期。BMI 24 以上的成人配合《超重与肥胖》附册看（附册不是计划，不能单独选）。
- 未成年人按**学段**选，不按年龄：12 岁已经上初中的用 13–17 岁版，13 岁还在读小学的用 6–12 岁版。
- 能导出的成品里，也有一些动作暂时照成品原文做（交替动作、有氧和单车、65 岁以上的平衡动作等），导出时命令会逐条列出来。
- **不覆盖**：学龄前儿童（0–5 岁）；孕期、产后 6 个月内。确诊慢性病的先问医生；残障人士在医生或康复治疗师指导下选择活动；65 岁以上最近一年跌倒过的，先做一次正式的跌倒风险评估，医生同意以后可以用椅子辅助版（成品第〇章有照官方标准写的《跌倒风险自查》，在家做的那一次不是正式评估）。

## 这一版能做什么、不能做什么

**能做**：

- 建档（入口问卷、安全筛查、上床时间、选成品）、四种评估、每周复盘、个人计划单、全家菜单，都由 agent 按 `.claude/skills/` 的流程走，每一步由命令检查。
- 按训练单和个人进度导出每天的跟练课程和课程包；起始期、稳定期，保持、减脂、增肌三种目标。
- 跟练：报数默认每次开始时报，呼吸提示"每组领几次 + 之后响提示音或安静"（65 岁以上、有高血压或没确认的至少响提示音）；暂停、跳段、屏幕常亮、全屏，切到后台自动暂停；动作示意动图。
- 练完记录感受、不适，保存或分享；agent 用导入命令写进档案，周复盘照它决定加不加量。

**边界和已知限制**：

- **全在本机**：没有账号、服务器、同步和推送提醒；手机和电脑之间靠自己发文件（课程包、练习记录）。
- **手机**：编排器和课程包是离线网页。电脑、安卓（Edge、夸克，从文件管理器打开）测过；**iPhone 没测**，从"文件"打开 .html 可能只是预览、不运行脚本。安卓 Edge 不给屏幕常亮时用备用办法；夸克没有系统语音时用内置语音。
- **新手培训期**：模板里已经有《培训期：第 1 周怎么练》一章、跟练要领卡和规则（阶段 9 的模板部分）；**主仓库还没接上**——导出的课程不带开头的呼吸练习和动作讲解，呼吸提示按"领 2 次 + 提示音"（模板里"没有培训期"的那一种），培训期照成品原文做。
- 编排器不能导出 MP4；导出的音频、视频只用内置语音。
- 计划没有专业人员审核；不覆盖学龄前儿童和孕期、产后 6 个月内。

## 安全底线

能用代码查的都由代码查，不靠 agent 记忆：

- **安全筛查**：有任何一项"是"、或者 65 岁以上的人，医生同意前不出计划，只建议先问医生；孕期、产后 6 个月内不出计划。
- **不编处方**：组数、次数、强度、休息、官方数字都来自成品原文；区间取较轻松的一端（次数、组数、时长取下限，休息取上限）。课程由 `npm run course -- export` 从训练单导出，自带检查，0 错误才写文件。
- **复盘放行**：每一周结束都要有周复盘，没放行导不出下一周的课程。个人进度（难度级、次数、重量）只能照成品规则改，每次改动写规则和依据，`npm run profile -- check` 重放核对。
- **不适就停**：打卡或练习记录里出现疼痛、头晕、胸闷，停止加量，按成品里"疼了怎么办"处理，必要时建议就医；这一段里（或上一周）出现过，个人进度就不再往上加（稳定期按 4 周一轮算）。
- **稳定期不新写处方**：稳定期的训练单由起始期标准段派生；进稳定期只有两条路（段末到了进阶线、有基础而且测试达线），周期末的结论由命令重算，该回起始期的不留在稳定期。
- **年龄红线**：对 6–12 岁、13–17 岁不谈体重、热量、减肥、排名；不给 65 岁以上安排跳跃、闭眼、憋气。

## 开始

1. 把模板仓库 `YangXia-templates` 放在本仓库的 `templates/` 下（它是独立的 git 仓库，本仓库已忽略这个目录），或者设置环境变量 `YANGXIA_TEMPLATES` 指向它。用这条命令确认找到了（打印模板仓库的位置）：

   ```bash
   npm run templates
   ```

   > **这一版（主仓库 v1.0.0）配模板 v1.0.0**：模板仓库检出标签 `v1.0.0`（`git -C templates checkout v1.0.0`），它在 v3.4 之上加了阶段 7 的动图、补图批次和阶段 9 的培训期内容；用别的模板版本，课程包、动图、离线样例可能对不上。更早的模板里，各功能最早需要的模板版本：`course export` 用到的训练单和规则参数（`templates/dist/data/`）从模板 v3.0 起在 `main` 上（标签 `v3.0`）；更早的版本只有成品。稳定期成品和规则（v4 阶段 3）从模板 **v3.1**（标签 `v3.1`）起有；用 v3.0 的模板，起始期的功能照常，档案里有稳定期的段会提示先更新模板。65 岁以上的跌倒风险自查（v4 阶段 3c）从模板 **v3.2**（标签 `v3.2`）起有；更早的模板没有自查规则，档案里的自查不核对、会提示先更新模板。成人稳定期的目标（v4 阶段 4）、《超重与肥胖》附册和官方食养指南附录（v4 阶段 5）从模板 **v3.3**（标签 `v3.3`）起有；13–17 岁、65 岁以上的稳定期和加项（v4 阶段 6）从模板 **v3.4**（标签 `v3.4`）起有；更早的模板没有目标的规则，档案里选了减脂、增肌会提示先更新模板。

2. 安装依赖：

   ```bash
   npm ci
   ```

3. 启用两个仓库的提交前检查：

   ```bash
   npm run setup
   ```

4. 打包编排器，生成 `apps/sequencer/dist/养夏跟练编排器.html`（单文件，双击打开，不用联网）：

   ```bash
   npm run build
   ```

   `course export` 用打包好的编排器出课程包；改了代码或更新了模板以后要重新打包，否则只出课程 JSON（命令会说原因）。

只想看计划：直接打开 `templates/dist/` 里的成品，先读 `templates/README.md` 选对版本。移动成品文件时要连 `img/` 文件夹一起移动。

## 和 agent 一起用

在本仓库里打开 Claude Code，直接说要做什么。agent 按 `.claude/skills/` 里的流程走，每一步都由检查命令把关。

一轮的样子：建档 → 导出当天的课程（课程包发到手机）→ 跟练、保存练习记录发回电脑、导入 → 周末复盘、决定下周 → 第 4 周结束后做月度总结、开下一段。成人起始期段末到了进阶线（或者有基础、测试达线的人建档时）进**稳定期**：12 周一个周期、3 轮，每一轮照起始期第 1–4 周的训练单，第 12 周做周期末评估，决定接着开下一个周期还是回起始期。

| 你说 | agent 做什么 | 写到哪 |
|---|---|---|
| "我想开始""给我家孩子建个档" | `onboard`：入口问卷、安全筛查、算上床时间、选成品、问训练单用到的条件和器材 | `profiles/<代号>/档案.json` |
| 建档的最后一步、"这一轮练完了"、换版本、断了很久 | `assess`：入门、段末、周期末、触发四种评估，结论由 `npm run course -- assess` 重算 | `profiles/<代号>/评估/` |
| "导出今天的训练" | `course-export`：先导入新的练习记录，再用 `npm run course -- export` 按训练单和个人进度导出这一天的课程和课程包 | `profiles/<代号>/课程/`（.json 和课程包 .html） |
| "这周怎么练" | `npm run course -- plan` 生成这一周的个人计划单：每天练什么、有氧做稳态还是间歇、习惯达标线、下次评估 | `profiles/<代号>/计划/` |
| （打开课程包跟练） | 练完点"保存练习记录"或分享，发回电脑；agent 用 `npm run profile -- import` 校验后写进档案（不手抄） | `profiles/<代号>/打卡/` |
| "这周练完了" | `weekly-review`：按成品的达标线和升级规则决定下周、改个人进度；起始期第 4 周后做月度总结、开下一段，稳定期第 12 周后做周期末评估 | `profiles/<代号>/复盘/`（.md 和复盘数据 .json） |
| "帮我排下周菜单" | `meal-plan`：按全家餐饮模板排菜单、算份量和采购量 | `profiles/<代号>/菜单/` |

安全筛查有"是"、或者 65 岁以上而医生还没同意的，不出课程；周复盘没放行，导不出下一周的课程。

## 常用命令

```bash
npm run setup                                              # 新克隆后启用两个仓库的提交前检查
npm run templates                                          # 打印模板仓库的位置，找不到时说明怎么放
npm run course -- intake [年龄段]                          # 入口问卷、成品列表和这个年龄段的筛查项
npm run course -- bedtime <阶段> <HH:MM>                   # 按公式算上床时间（如 初中 06:30），不要心算
npm run course -- moves <成品名>                           # 这份成品能导出的动作、处方原文、呼吸节奏
npm run course -- export profiles/<代号> <第几周> <哪天>   # 按训练单和档案导出一天的课程（可加 --out <文件>、--pick 组=动作；中断、生病回来的第一次加 --half）
npm run course -- assess profiles/<代号> <入门|段末|周期末|触发> [记录.json]   # 评估：列出要问、要测的项；给了记录就按规则重算结论、核对
npm run course -- plan profiles/<代号>                     # 现在这一周的个人计划单（写 计划/第N段-第N周.md，不手写、不手改）
npm run course -- check <课程.json> --profile <档案.json>  # 检查课程：按训练单和档案进度逐项核对，连同安全筛查
npm run course -- summary <课程.json>                      # 总时长、动作、组数
npm run course -- srt <课程.json>                          # 打印 SRT 字幕
npm run course -- cases                                    # 跑模板 manifest 里的红线校验样例
npm run profile -- check profiles/<代号>                   # 档案、周次推进、进度日志、练习记录、课程、课程包、计划单、评估、复盘和菜单的检查
npm run profile -- import profiles/<代号> <记录.json>…     # 导入练习记录：按格式校验、核对是这个档案的课、去重，写进 打卡/（--dry-run 只看）
python3 templates/tpl.py all                               # 改了模板后构建 + 校验
```

`npm run course -- check <课程.json> --no-profile` 只检查课程本身，给样例和开发用，不能据此把课程交给使用者。

```
  评估/<日期>-<入门|段末|周期末|触发>.json  评估记录（assess 写，结论由命令重算）
  菜单/第N周.md                          一周菜单（meal-plan 写）
  计划/第N段-第N周.md                    个人计划单（course plan 写，不手写、不手改）
  历史/第N段/                            新开一段时，上一段的 课程/ 打卡/ 复盘/ 可以整个移进来
```

- 个人数据（档案、打卡、练习记录、`.ics` 日历）只放在 `profiles/<代号>/`，不进 git，提交前检查也会拦；搜索工具搜不到这个目录，agent 只按文件名明确读取。
- 课程包和练习记录会在电脑和手机之间来回：发给自己（文件传输助手、AirDrop、数据线），不要发到群里；导入以后，下载目录、手机、聊天记录里的原文件可以删。课程包里只有这节课的内容，文件名带代号（不要用能认出人的称呼）。
- 用**代号**，不用真名。安全筛查只记"是 / 否"，不记诊断细节和用药。
- 训练单用到的几项条件（有没有高血压、骨质疏松，家里有没有别人、有没有跳跃场地、有没有家长在旁边）每项只记"是 / 否"，建档时会如实告诉使用者；没记的一律按"没确认"导出保守版本。
- agent 读档案时，内容会作为对话发给模型服务处理；除此之外不发往任何地址，也不放进链接参数。

## 开发

### 测试

```bash
npm test             # 单元测试（模板不在时，安全相关测试照样跑）
npm run typecheck    # 类型检查
npm run e2e          # 用离线样例打包编排器，用 Playwright 跑冒烟和动作示意测试
```

第一次跑冒烟测试前装一次 Chromium：

```bash
npx playwright install chromium
```

### 改编排器或课程核心库

- 按 `sequencer-dev` skill 的流程做。编排器的开发服务器：`npm run dev -w @yangxia/sequencer`。
- `apps/sequencer/reference/原版.html` 是重构前的原版，带别人的商标，只在本地保留、不提交；单元测试只用已提交的基线 `apps/sequencer/test/fixtures/original-baseline.json`，本地有原版时可以用 `npm run baseline` 重建基线。和原版的功能对照、怎么验证没走样，见 [docs/编排器功能清单.md](docs/编排器功能清单.md)。

### 改模板

- 在模板仓库里按 `templates/AGENTS.md` 的规则改、在模板仓库里提交（`template-maintain` skill）。不直接改 `dist/`：改 `content/` 或 `figures/` 后运行 `python3 templates/tpl.py all`，要求 0 错误 0 警告。
- 本仓库只读模板的发布物：`templates/dist/` 里的成品、`dist/manifest.json`、`dist/data/plans.json`、`rules.json` 和 `motions.json`；不读 `content/`，不 import 模板的代码。

### 提交规则

- 新克隆先运行 `npm run setup`。**不准**用 `git commit --no-verify` / `-n` 跳过检查，也不准改 `core.hooksPath`；检查没过就改，不绕。
- 在 Claude Code 里每轮结束会自动检查：模板有改动跑 `tpl.py all`，主仓库代码有改动跑单元测试，档案目录有改动跑 `profile check`；有错先修。
- 只提交必要文件：临时文件、构建产物、导出的媒体、个人数据、密钥都不提交，规则见 `.gitignore`。
- 依赖选发布超过两周的稳定版本，写死版本号，`package-lock.json` 一起提交。

### 命名

- 项目名称：**养夏 YǎngXià**。
- 给人看的用中文「养夏」：显示名、页面标题、界面文字、文档和成品文件名（如「养夏跟练编排器」）。
- 给程序读的用英文：目录、命令、npm 包名（`@yangxia/…`）、数据格式标识（`yangxia.course/1` 等）、git 标签、仓库名（`YangXia`、`YangXia-templates`）。
